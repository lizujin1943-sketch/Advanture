# 海域进度与恢复事件实施说明

2026-10-22：共享委托现在会开放新鱼群；长时间没有鱼获或连续处理水怪攻击后，出现短暂恢复窗口和可正常捕获的近岸普通鱼。规则由纯 C# 模拟维护，Unity 读取确认态显示海域与倒计时。

## 当前规则

- 初始 24 个基础鱼群按 8 个方向、3 档距离排列；开局近圈 8 群为普通物种、1～3 kg、普通等级，每次刷新仍保持这条初始装备可尝试的路径。
- 完成第一份委托开放中圈 8 群，普通至稀有物种、2～6 kg、最高 Boss 等级；第二份开放远圈 8 群，稀有至传说物种、2～6 kg、最高 Boss 等级。物种沿用目录权重，个体等级沿用 90／9／1 比例。这里的 Boss 仅为现有收益／挣脱力等级，没有新增上岸行动。
- 每档第一次开放时，尝试在近岸提供一波轻鱼：第一档非稀有进阶物种，第二档稀有物种；均为 1～2 kg、普通等级。场地或槽位暂不可用时留待后续，跨多档只提供当前最高档。
- 连续 90 秒没有成功捕获，或 30 秒窗口内水怪发射／被钩子打断累计 3 次，触发 20 秒恢复窗口，至少间隔 60 秒。只暂停水怪冷却及新的前摇，已开始的前摇、水球、食人鱼和落水风险照常运行。
- 恢复时尝试补充最多 2 条普通轻鱼。临时鱼存在 30 秒，必须真实钓取，沿用合钓、反向抢钓、耐力、金币、鱼骨和委托结算。不会直接增加玩家资源。只有成功捕获事务重置无鱼获计时，食人鱼也计入；失败结算与脱钩不计。
- 临时鱼已挂线或正在挣脱时，到期也不会消失；捕获或挣脱结束后释放槽位。下一波不会覆盖这些鱼。没有岸上活人、没有位置或没有空槽时不生成新鱼；有存活玩家时仍可获得恢复窗口。
- 生成位置使用当前平台地块，检查完整游动线路、鱼体余量、保留格和世界边界。扩建挡住未挂线临时鱼的路线时，该鱼退场；已挂线者保留。保存的历史位置允许被后续扩建覆盖，恢复存档不会因此吞掉已挂鱼。
- 海域阶段只随委托推进，不随时间开放。恢复机会优先于阶段波次；普通近圈始终保留。

## 配置与接入

正式配置是 `samples/TacticalGame.Unity/Assets/HookIsland/Data/OceanSettings.asset`，由 `FishingSettings.asset` 引用。`pauseNewMonsterAttacks` 可关闭恢复窗口对水怪的暂停，仍保留补鱼。上述时长、阈值、基础解锁表、临时槽数和六组鱼生成范围均可配置；这些是实现者初值，尚非长期平衡结论。

修改后执行 Unity 菜单 `Tools/Hook Island/Install Fishing Equipment`，重新导出并刷新 `PlatformMap.bytes`。未绑定或关闭配置时保留原来的全部鱼群行为。正式地图有 24 个基础槽和 2 个临时槽；总数上限 32，临时槽可配 1～4 个。

- `OceanConfig`、`OceanState`：不可变参数与确认状态。
- `OceanRules`：阶段、加权生成与动态鱼群位置。
- `OceanPlacement`：确定性岸边位置与完整游动路径检查。
- `OceanSystem`：事件调度、临时槽生命周期、成功捕获通知。
- `OceanStateCodec`：快照格式及有效性校验。
- `HookGame.Ocean` 与捕获事务：在统一帧序中编排，先处理实际捕获，再判断恢复条件。
- `CommissionHud` 与 `FishingPresentation`：只读海域行、临时鱼方向和水纹。隐藏槽不可见、不可命中，不阻挡建造。

海域进度接入时规则／状态／房间协议为 **19**，输入 **9**，地图 **HIMD**，状态尾增加 **OCN1**。后续终局与外围商人接入后，当前规则／状态／房间协议为 **21**、输入 **10**、地图 **HIMF**。旧构建、地图和快照明确拒绝，本轮不迁移旧档。新档保存事件序号、计时、临时位置和已提供阶段；重开局全部按新局规则清零。

## 验证

```sh
dotnet run --project tools/HookIsland.Tests -c Release -- --simulation-only --filter=ocean_
dotnet run --project tools/HookIsland.Tests -c Release -- --filter=ocean_real_udp
./scripts/verify-hook-restart.sh network_ocean
python3 scripts/run-island-party.py --app artifacts/ocean-progression/HookPlatform.app --players 4 --ocean
./scripts/verify.sh
```

`--ocean` 使用显式启用的开发场景：三档基础鱼群、缩短的委托与恢复计时，通过普通移动／出钩完成两档解锁并捕获恢复鱼。没有运行时奖励或进度注入；自动操作者不进入发布程序集。1／2／4 人均参与捕鱼，多人需实际观察到合钓。另用正式 24 个鱼群、默认委托与恢复计时验证初始竿的可达性；该受控场景关闭敌人，不能据此声称正式战斗难度已平衡。

阶段证据保存在 `artifacts/ocean-progression/verification-summary.json`：确定性规则 25 项，1／2／4 人 × 0／3／6 帧输入延迟 9 项，默认数值可达性 1 项，真实 UDP 1／2／4 人 3 项，重开清零 2 项；Unity 编辑器 68 项。开发和发布构建均零错误／警告，发布程序集不含新增自动验收类型。

原生 1／2／4 人分别于第 1015／931／1001 帧完成两档解锁和恢复鱼捕获；所有玩家实际捕鱼，多人分别观察到两根／四根钓线，各端完整 checkpoint 逐字节一致，日志无运行异常。阶段、恢复和临时鱼画面已检查；`stage0.png` 采集过早仍为大厅，不作为初始海域视觉证据。玩家紧贴时，既有头顶耐力／主辅提示仍会重叠，保留在整体可读性待办。

`./scripts/verify.sh` 已完整退出 0：钓鱼与 UDP 250/250、库存 26/26、角色 28/28、游泳 27/27、敌人 45/45、复活 26/26、重开 14/14，其他框架／存储／传输／战术样例检查也通过。独立最终复核无 Critical／Important／Minor，新生产源码与复核时 38 份摘要一致。本轮联机验证限本机真实 UDP，不代表互联网长时稳定性或最大扩建帧预算已经验收。

本阶段不包含终局巨物、M2～M5 商人可达路径、晚加入／重连，也不包含用户延后的 Boss 上岸逻辑。海域机会通过不代表这些后续玩法已完成。
