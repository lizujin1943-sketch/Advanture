# 倒地、救援与付费复活

规则来源：2026-10-23 玩家确认单人死亡自动扣费复活、金币不足立即失败；多人倒地即可主动付费复活，也可等待队友免费救起。正式场景为 `samples/TacticalGame.Unity/Assets/HookIsland/Scenes/HookPlatform.unity`。

## 操作与结算

- 单人血量归零时跳过 60 秒救援等待，不显示救助窗口。有足额金币便在同一模拟帧自动扣费、回到安全出生区域；金币不足则立即游戏失败。
- 多人血量归零进入倒地，不能移动、游泳、出钩、交易或建造，装备和背包保留。此时即可点击“立即复活”，或继续等待队友免费救起；只有成功付费复活才扣金币。
- 队友与倒地者都在有效地面上，距离不超过 1.5 米且中间没有障碍／水面时，按住 **R 3 秒**免费救起，恢复 30% 最大生命（至少 1 点）。不补耐力或饥饿，耐力恢复重新等待。
- 松开 R、移动、出钩、开菜单、受伤、被拖拽、击退、离开距离或施救者离线会中断进度。多人同时施救不加速；换人后从头开始。
- 水中倒地先用钓竿拖上有效地面，再近身救起。拖拽不会治疗，60 秒倒计时照常推进。救援恰好完成的那一帧优先于超时死亡。
- 多人 60 秒到期进入死亡。死亡时解除钩索连接及残余击退，此后不能继续被钩救或近身救起，仍可主动付费复活。
- 倒地和死亡页均显示个人余额与费用。付费成功回到出生点附近可站立且无人占据的位置，解除拖拽与击退；默认满血、满耐力，保留装备、背包和饥饿。不足全额或找不到落脚点时不扣款。
- 费用在本次血量归零时锁定，实际复活成功时扣一次：`10 + floor(倒地时本局模拟秒数 / 300) × 5 + floor(倒地时个人金币 × 10%)`。等待不会继续涨价，不使用队友钱包。免费救起清除报价，下次倒地重新报价。
- 多人仍在所有人均已死亡，且没有任何人能支付自己的锁定费用时失败。全队倒地不立即失败；有人正好付得起也不失败。单人余额恰好等于费用时正常复活，余额归零。

## 配置

`Assets/HookIsland/Data/RevivalSettings.asset` 由 `FishingSettings.revival` 引用。创建房间时写入确定性地图配置，所有客户端必须一致。

| 字段 | 默认值 | 含义 |
|---|---:|---|
| `downedSeconds` | 60 秒 | 多人倒地救援窗口，单人跳过 |
| `rescueSeconds` | 3 秒 | 连续施救时间 |
| `rescueRangeMetres` | 1.5 米 | 近身施救范围 |
| `rescueHealthFraction` | 0.30 | 免费救起恢复生命比例 |
| `baseFee` | 10 G | 固定费用初值 |
| `growthFee` | 5 G | 每个完整时间段增加的费用 |
| `growthIntervalSeconds` | 300 秒 | 固定费用增长间隔 |
| `balanceFeeFraction` | 0.10 | 倒地时个人余额的收费比例 |
| `respawnHealthFraction` | 1.00 | 付费复活生命比例 |
| `respawnStaminaFraction` | 1.00 | 付费复活耐力比例 |

时间按 30 Hz 房间模拟帧计算；现实离线时间不计入。金额向下取整并防止溢出。

## 实现边界

纯 C# 的 `RevivalSystem` 管理生命周期和原子结算，`RevivalStateCodec` 保存并校验倒计时、施救者、倒地报价、支出账本、倒地代号和请求回执。Unity 的 `RevivalController` 只提交输入，`RevivalOverlay` 只呈现确认状态。复活扣款不进入通用帧同步核心。

每次倒地生成 `DownedId`，即使后来免费救起，也不会复用同一个代号；`Deaths` 继续只统计最终死亡。付费请求的既有 `DeathId` 字段绑定本次 `DownedId`，并使用递增请求号；成功和失败都保存回执。重复发送、免费获救后再次倒地下的旧请求及读档重发不会再次扣款，失败后需新的主动请求。同帧先执行已提交的付费请求，再处理免费救援进度；已在此前确认帧获救的请求不会扣款。救援状态在水怪的击退／离线状态读完后统一校验。

按实际入场人数区分单人和多人：预留空席位不计人数，已经入场的离线队友仍计入多人。单人自动付费仅在首次死亡转变时尝试；角色离线时不自动扣费，重连后可主动复活。找不到安全落脚点则保留死亡状态和金币，可稍后主动重试，不会暗中重复支付。

当前规则／房间协议 **24**、输入 **11**、状态 **23（HISF）**，地图格式保持 **HIMF**。旧版本快照和不一致的房间配置明确拒绝，不提供跨版本迁移。现有热加入和重连边界见[晚加入与断线恢复](live-room-recovery-implementation.md)。

开发验收驱动需显式 `-island-revival-smoke 1`，只在 Editor／Development 中编译，正常启动不自动游玩，正式发布包排除该驱动。它通过正常输入钓鱼赚金币、落水、钩救、近身施救和倒地立即付费复活，不向正式玩法注入资源。
