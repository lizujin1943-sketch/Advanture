# 灰隼补给站：小型军事基地尸潮沙盒

日期：2026-11-18。状态：地图设计提案，未搭建 Unity 场景，未验证战斗、寻路、多人或性能。本文所有尺寸、时间、敌人数与设施效果都是原型假设。

后续修订：根据用户要求加入战机、营房和真实基地原型，当前布局见[达克斯福德原型 V2](military-airfield-sandbox-v2.md)。本文保留为第一版方案记录。

## 体验与范围

用户要求：小型军事基地、沙盒探索、大规模尸潮攻击、防守、几个有价值的守卫据点。沿用本轮的类幸存者方向，暂按 1–4 人、俯视或斜俯视、玩家亲自输出设计。

建议将基地设定为撤离失败的边境补给站。玩家在四处固定据点之间探索、收集材料、建造工事和选择阵地。体验目标是“提前观察来袭方向，选择有利位置；防线受损时主动转移；喘息后能够夺回据点”。四个据点开局均可到达，不按顺序解锁，也不要求同时驻守。

本地图承接[营地守夜草案](zombie-camp-defense-design.md)中玩家主输出、工事阻挡与减速、有预警的突破与退守原则；是独立地图提案，不覆盖原有 40×34 米营地布局。旧稿中的白天外出大世界、主屋被毁判败和固定昼夜时长不自动成为本图要求。当前枪械无限备用弹药的基线不因“军需仓”改变。

## 布局选择

考虑过三种结构：单核心堡垒能聚焦守城，但可选阵地少；四角独立堡垒容易迫使玩家长距离分散；采用围绕中央操场的四据点结构，提供内侧快速支援和外侧长距离绕行。选择此方案是设计建议，尚未经过用户或试玩确认。

## 尺度与坐标

坐标原点在地图西北角，X 向东、Y 向南，单位米。完整画面范围 96×80 米，含外侧来袭带；基地围界为 (8,8)–(88,72)，约 80×64 米。相邻据点的实际折线路程约 25–40 米，若移速为 3–4 米/秒，则空场转移约 6–14 秒；这不是实测结果。镜头、碰撞与实际移速确认后应整体调尺。

## 四个守卫据点

### A：南门检查阵地——接住主潮

- 位置：防守地面约 (35,55)–(61,67)，核心站位 (48,59)。南门到射击线之间保留空地。
- 形态：两段矮工事分列南门内侧，前方为宽入口；后方连接操场，左右接外围环路。门口不摆 S 形水泥迷宫。
- 优势：最早看到南方尸群，正面射界清楚，可分两侧射击，适合群体输出和基础减速工事。
- 代价：正面来敌最多；东西侧门被突破后，侧后方会受压；没有就地维修材料供应。
- 撤退：向西经 (30,53) 进入 B 的南侧出口，或向东经 (72,53) 进入 C 的南侧出口；操场也可通行，但暴露更大。
- 识别物：倒斜的道闸、两辆军车、检查站标识。军车不得遮死出口或卡住中央穿行线。

### B：维修车间院——可经营的稳定据点

- 位置：核心站位 (30,40)。L 形不可进入厂房由 (18,26)–(32,32) 与 (18,32)–(22,46) 两个体块构成；院内主要活动范围约 (23,33)–(36,48)。
- 形态：东向大开口约 y=36–44，南侧人员/推车通道 x=27–33；西与北侧厂房挡住直接来敌。南沿矮墙只占 x=22–27 与 x=33–36。
- 优势：要照看的接近面比较集中；旁边固定维修台与有限零件容器，适合修理工事、换弹和掩护队友。
- 代价：厂房遮住西侧来敌，不能提前清掉全部后勤门尸群；围进院内后活动空间有限，南通道可能被绕后的敌人占据。
- 撤退：东侧到操场；南侧到 A；向北绕厂房东侧可抵 D。两处直接出口不能被美术杂物堵住。
- 识别物：吊臂、拆卸发动机、检修工具。检修坑首版只作为封闭布景，不做容易掉落的玩法坑。

### C：军需仓装卸院——补给与侧翼争夺

- 位置：核心站位 (71,40)。仓库实体为 (65,25)–(78,32) 与 (78,32)–(82,48)。活动范围约 (64,33)–(77,48)。
- 形态：西侧装卸开口 y=36–44，南侧通道 x=69–75；南沿工事只占 x=64–69 与 x=75–82。
- 优势：有限的建材与特种补给箱位于此处，控制后方便补充防御消耗；能向操场提供侧向支援。
- 代价：东破口近，敌人能沿仓库南北两端迂回；箱堆只形成两组障碍岛，不能把院子做成看不到尸群的货架迷宫。
- 撤退：向西跨操场到 B；向南到 A；沿仓库西侧向北到 D。
- 补给边界：不把普通备用弹药变成必需消耗，不让玩家靠弹药枯竭被强制赶出阵地。有限补给不按波次自动刷新；后续补充应来自明确的补给事件。
- 识别物：军绿色物资箱、仓库编号、折叠遮雨棚。

### D：通信站前院——集结与有代价的退守

- 位置：核心站位 (48,24)。北侧通信楼实体约 (35,14)–(61,20)，前院范围 (40,20)–(56,29)，南侧为可射击但阻挡移动的矮工事。
- 形态：西、东两个侧向开口约 5–6 米；两侧均连接中央与外环。前院、坡道首版处于同一可导航平面。
- 优势：通信楼遮住北侧直接来敌，面向操场的观察与支援位置较好；通信终端可提供明确来袭方向，适合集结、救援和短期退守。
- 代价：空间较紧，不能容纳持续涌入的大群敌人；北门一旦破坏，敌人从通信楼两侧压进两个出口。无独占补给和无敌高度。
- 撤退：西出口通 B，东出口通 C；南沿矮工事不能在图纸上冒充可穿越捷径。
- 识别物：通信天线、低矮防爆墙、故障信号灯。塔顶和屋顶为布景，不是玩家安全射击位。

四点之间可以交替使用。推荐的首次体验是 A 拦截→选择 B/C 整理→视局势借 D 集结，但这不是强制关卡流程。D 失守或北门突破均不直接判败；本轮不加入固定主屋血条胜负条件。

## 尸潮组织与据点失守

建议初始南、西、东是已存在的来袭方向，北门为有预兆的可破坏入口。开局一次主压一个方向，后续形成“一个主潮方向＋一个侧翼方向”；三向压力只作为后期短峰值候选，不默认每波从四周均匀灌入。单人减少并发进攻方向、奔跑者与破坏者数量；多人增加同时需要处理的威胁，具体数值待测。

来袭从地图外部道路/集结带进入，经围界门洞和建筑绕行到达阵地。不得在可见地面、已清空的封闭院内或玩家身边凭空生成。地图外的生成点与地图内入口是两层：观察覆盖某个生成区时，应改用其他不可见集结点或推迟生成，不把入口的固定坐标直接当出生坐标。

可用三类敌人先检验空间：普通感染者制造持续压力；少量奔跑者追击撤离和威胁侧翼；有明显重击前摇的破坏者攻击可达工事。工事倒塌要有损坏阶段、声音和来袭方向提示。整波路径选择先确定，敌人不会因玩家换据点而瞬移或无预警改到前方刷出。

建议的单轮压力节奏：方向预警与布防→主潮进入→有预警的侧翼增援→破坏者制造突破风险→增援间歇、清理与夺回。时间由清群速度决定，首版不锁死整局或昼夜时长。玩家能选择坚持、提前撤离、分队短暂接应或放弃一处工事。

要营造“大规模”，让多个宽入口容纳连续队列，并让玩家能在接触前看到尸群展开。不要用一个狭窄门洞把数百敌人堆成互相卡死的点。普通敌人仍遵守碰撞、攻击与阻挡规则，远处景观尸群不计入可战斗敌人，更不能据此宣称已支持对应规模。

## 工事与沙盒选择

- 初始提供足够做一处基础防线的材料，玩家自行选择投资 A/B/C/D；固定设施不必全部占领。
- 开阔院内可摆放矮墙、可破坏路障、减速带与地刺。强碰撞物不能与角色/敌人重叠，维修和建造有耗时、材料代价，不能瞬间封住敌人身体。
- 5–6 米的必要交通带应保持可通过；若允许玩家在带内放墙，则必须仍能打开/拆除，而且敌人能攻击并破坏堵路工事。规则须显示在预览中，不能依赖隐藏寻路特判。
- 普通敌人不能穿墙或被人为封路后停机。堵住全部路口时选择能到达的阻挡工事攻击；“守据点”和“放弃据点”都应有可理解的后果。
- 固定战场结构不会自动长回去；修复既有防线与夺回材料容器都是主动行为。补给消耗、墙体破坏和波次结算需持久化，但具体存档接入不在本次设计范围。
- 自动炮塔不作为本图成立的前提；若后续加入，仍需验证玩家是否保持主要战斗参与。

## 视觉与俯视可读性

中央操场采用低细节混凝土地面，行走区域和建筑边界清楚。四处地标用道闸/吊臂/箱堆/天线区别，并配文字或编号，不只靠颜色。建筑不追求真实基地面积，远景营房和车辆可以留在围界外补充规模感。

所有高建筑、棚顶和天线在实际镜头下检查遮挡；必要时对玩家遮挡部分淡化，但不改变权威碰撞。夜景保留敌人、工事缺口与队友轮廓，警报灯不能覆盖危险提示。每个据点至少保留一个能提前观察来敌的位置；地图上的几何可达不等同于玩家已经能看见目的地。

## 最小白盒与验证

首轮只搭围界、四个建筑体块、据点矮墙、两条支援线与外环。先用四处入口和少量普通敌人验证可达性，再加可破坏工事与奔跑者，最后做大群压力和破坏者。地图上的设施效果可先不实现，不能用设施奖励掩盖空间本身的问题。

需要回答：

1. A 正面被压时，四名玩家能否看懂并通过两侧撤退路线？两条路线是否经常同时在没有预警时被封？
2. B/C 是否都值得驻守？是否有一个靠角落站桩或默认补给就永久优于其他据点？
3. D 的两条出口是否能让玩家救援转移？北门开启后是否只剩无法归因的必死局面？
4. 外环是否演变成无成本无限绕圈？应优先调整可观察的侧翼压力、射界与路线长度，不通过敌人瞬移补漏洞。
5. 建墙堵口后敌人能否持续攻击工事？同门大量敌人是否拥堵、穿透或停摆？
6. 尸潮下角色、特效与缺口是否仍看得清？俯视屋顶遮挡、友伤射线和倒地救援须另做实机验证。

规模测试可从同时 80 / 160 / 240 个可战斗敌人的三档开始，记录目标设备、帧时间、模拟耗时、寻路预算、入口吞吐和四客户端一致性；这些是递增测试输入，不是性能承诺。总波次数量与同时活跃数量分开配置。达到预算之前不为了“看起来更多”牺牲规则一致性。

本轮完成 8 组转移/来袭路线中心线的抽样穿墙检查、交互脚本语法检查，以及 736/320 像素视口下浅色与深色地图的浏览器查看；已操作验证图层与据点选择。窄屏最终地图容器宽度与内容宽度均为 288 像素。中心线检查不包含角色半径、转角通行、尸群挤压和真实视线。
