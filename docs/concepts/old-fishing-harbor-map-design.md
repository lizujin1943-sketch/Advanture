# 旧渔港：双环登陆战地图设计

日期：2026-11-03。状态：设计提案，未修改 Unity 场景、地图数据或玩法代码。尺寸、敌人分路和战斗节奏均待白盒试玩验证。

> 后续方向已调整为[白天搜集、夜间守营的合作射击](zombie-camp-defense-design.md)。本图保留为旧方案及局部营地／遭遇区的参考，不再作为捕鱼核心循环下的完整新地图执行。

## 设计意图

将目前 6×6 米的起始木平台改为一座半废弃的海上渔港。四人仍围绕钓鱼、收集、扩建和购买装备游玩；敌人登陆时，空间提供绕船换位、侧路支援、掩护换弹和钩救队友的选择。

保留 2×2 米木地块，不强制换成天然岛屿。地图的趣味来自可辨认的船坞、码头、岸口及它们之间的联系。搁浅渔船和封闭货棚形成实质阻挡，装饰不承担隐形碰撞。首版不依赖跳跃、攀墙、二层地形或可破坏桥梁。

## 现有能力与设计尺度

| 项目 | 当前依据 | 对地图的影响 |
|---|---|---|
| 玩家陆地速度 | CharacterSettings：3 米/秒 | 横穿主要活动区的目标约 8–12 秒；不是把人物和镜头一起缩小 |
| 螃蟹 | 当前配置 3 只、2 米/秒，攀爬 1.5 秒 | 先沿用数量验证空间；不能依赖单只螃蟹跑赢玩家制造压力 |
| 初始钩索 | 线长 4 米；出钩时禁止移动 | 普通鱼岸边需有提前可见的登陆预兆；能收钩后退回环线 |
| 沙漠之鹰 | 射程 12 米；换弹 1.8 秒；队友伤害 50% | 主要交火距离先按 5–10 米设计；左右换位有价值，避免从一点射穿全场 |
| 地块 | 2×2 米；玩家体型按约 1 米高设计 | 主路净宽以 4 米为目标，集结处约 6 米宽；2 米宽只用于短的次要通道 |
| 镜头 | 第三人称及跟随玩家的俯视模式 | 地图图纸是全景概览，游戏仍跟随人物，不为看全地图把镜头拉远 |

以上时间是由距离与速度推算的设计目标，不是实测结果。四人拥挤、收钩、受击、换弹和转角会增加实际耗时。

## 平面结构

外轮廓为错落的木码头，最大占地 28×24 米。图纸包含 117 块甲板，面积 468 平方米；扣除船体、货棚和商店的保守占地后，通行面积约 408 平方米。水槽不计入甲板。该面积约为原 36 平方米平台的 11 倍，首轮白盒可以据实际空旷程度缩减外缘，不能以填满矩形作为扩容目标。

布局以一块中央集结区联系两个环路：西侧绕船坞，东侧绕货棚及内港码头。北、南和西侧的钓鱼边缘与环路相接。敌人从西、东、东南三处低岸口登陆。

| 区域 | 布局与用途 | 玩家选择 |
|---|---|---|
| 中央集结区 | 保留约 6×6 米集结空间；小商店靠南侧，出生点避开商店实体；向多个方向通行 | 集合、购买、转移和近身救援；这里没有免伤或敌人禁入规则 |
| 西侧船坞 | 一艘约 4×8 米的搁浅渔船作为不可进入的实体；北、南都能绕过 | 引敌走一侧，队友绕另一侧停步射击；船后换弹或暂时切断追击路线 |
| 东北货棚 | 约 6×4 米的封闭货棚，北侧与南侧均留路 | 将东岸敌人的直冲路线拆开，防止中央站桩覆盖所有入口 |
| 东侧外码头 | 约 4 米宽的外侧步道，经北、南连接处回到中央 | 较长但清晰的侧路；能救援、绕后，也更接近海面风险 |
| 内港水槽 | 2×4 米，左右有落脚面；桥下在美术上与海水连通 | 初始 4 米钩可触及槽内落水队友；不假设能把岸上队友拖越水槽，也不要求跳过水槽 |
| 三处钓鱼边 | 北端、南端和西侧，保留约 4–6 米宽可站位岸线 | 每处有沿岸两个方向的撤离路径；登陆预兆可见，不能成为完全无风险的刷鱼点 |

### 码头与岸口

- A 西岸口：约 4 米宽，敌人上岸后可沿船头或船尾接近中央。
- B 东岸口：约 4 米宽，敌人可绕货棚进入中路，也可转入外码头。
- C 东南岸口：约 4 米宽，接入南连接道；用于打破玩家始终绕同一方向逃跑的习惯。
- 岸口用低斜板、爬痕和破损护边表达可登陆，实体坡面与甲板衔接。不能用垂直悬空台阶假装坡道。
- 钓鱼边保持开放；保留落水风险。主要通路的护边与装饰只作局部提示，不把环路围成不能回钩的走廊。

### 图纸坐标与可复核尺寸

图纸使用独立的平面坐标：左上角为 (0,0)，向右、向下分别递增，单位为米；它不是已应用到游戏的世界原点。每格 2 米。下面是每行的甲板列索引，行列从 0 开始：

| 1 | 3–9 |
| 2 | 1–11 |
| 3 | 1–13 |
| 4 | 0–13 |
| 5 | 0–12 |
| 6 | 1–12 |
| 7 | 1–9、11–12 |
| 8 | 2–9、11–12 |

船体占 x=6–10、y=8–16；货棚占 x=16–22、y=6–10；商店保守占地 x=12–14、y=16–18；水槽位于 x=20–22、y=14–18。主路要按角色与螃蟹完整体积检查净宽，不能只检查中心点。装饰不得再吃掉这些宽度。

## 一次战斗如何发生

示例：两人在西侧钓鱼，一人在集结区，一人在东码头收材料。

1. 西岸出现接近水纹和攀爬动作，钓鱼玩家选择完成当前回收，或右键提前收钩后退；主动放弃收获仍遵守现有断连规则。
2. 西岸螃蟹开始接近。第一位玩家沿船头退，第二位沿船尾换位；船体让敌人不能直线追穿，也阻止队友隔着船乱射。
3. 东岸螃蟹迫使远端队友选择留在外码头牵制，或经南连接道回援。两条环线在中央可互换，不需要在一条窄桥上相互挤过。
4. 队友换弹或受伤时，另一人留在不同射线方向掩护。50% 队友伤害使“所有人站成一列射击”有明显代价。
5. 有人落入内港水槽，附近玩家可用初始钩索拉回；岸边倒地者先由队友掩护，再近身救援。两类救援沿用既有规则。
6. 清理敌人后返回岸边继续钓鱼、补给和扩建。战斗不应把钓鱼玩法持续挤出地图。

## 敌人行为配套：是新增设计，不是地图已经具备的能力

现有螃蟹会寻路追逐可达玩家，并不会主动协同包抄。单纯放大地板或放美术障碍不会自动产生上述行为。

第一版白盒建议仍使用当前 3 只螃蟹，主要从两处岸口施压，例如 A 两只、B 一只；C 在后续遭遇中替换一个入口。不要把三处岸口同时等量铺满作为默认节奏。沿用现有攻击前摇、攀爬和击退机制。

需要为新地图补充的最小规则：

- 明确登陆段，登陆位置落在有效岸口；不要沿新增的整圈海岸随处瞬间出现。
- 主要目标仍是可达玩家；其中一只可选择另一条可达侧路作为阶段目标，形成可读的绕行。它不传送到玩家背后，不用突然加速抵消玩家换路。
- 登陆与绕行分配发生在权威模拟中；使用稳定顺序及可保存的路线阶段。不是 Unity 本地各自随机决定。
- 环路被堵或玩家离开后，重新选择可达路线，不对一条失效的路线永久坚持。
- 先检查是否“同一队玩家一直绕一个圈就完全不需要战斗”。若确实如此，优先调整入口组合和路程，再考虑额外敌人；不要直接提高螃蟹速度追上玩家。

岸口附近需有水纹、音效或明显攀爬动作。保留 1.5 秒攀爬时间；岸口到主要钓鱼站位之间尽量留 6–10 米陆上接近路径。是否足够完成收钩并脱离危险必须实测，不能仅凭总距离认定可反应。提示的空间位置、方向与声音范围需要在两个镜头模式下验证。

## 扩建、资源与原玩法的衔接

- 这版方案改变了“最初只有 9 块地”的开局：免费空间已足够迂回作战，建造价值转向钓更远的鱼、接近商船、增加站位。它是本提案的取舍，尚未写回正式规则。
- 玩家仍按当前每块 4 木材或 4 鱼骨的配置向外铺地。预置渔港不能通过拆除兑换成免费材料。
- 船体、货棚和两格内港水槽属于预置占用／保留区；不能填地消除核心绕行。外围保留可建区域，在商船航路与攀爬坡道上清楚标示不可建范围，建造预览与权威校验使用同一份规则。
- 螃蟹也能进入玩家新增平台；铺出桥梁不能形成它明明能走却被强行禁止进入的永久安全区。新增平台不会自动成为新的出生口。
- 原商船距原点的 10、14、18、22 米位置不能原样使用，否则可能落在新甲板内。需按新岸线外移，并按“接近交互范围所需铺设的格数”重新校准成本，仍保留先近后远的推进关系。
- 鱼群区域要围绕**起始岸线**重设。普通鱼带先按离岸约 2.5–4.5 米设计，中距离约 6–10 米，远处约 12–18 米；仍遵循已有物种和海域解锁规则。
- 上述距离为可调提案，不能让所有普通鱼都落在初始钩索范围外。鱼的游动路径不能穿过甲板或船体，内港水槽不刷正常鱼群与敌人。
- 玩家扩建后，鱼群不会随新岸线不断向外逃。扩建与升级钓竿应确实带来更大的可达范围，也不能因放大初始平台而免费触及原先远海鱼群。
- 商店、出生点、任务等须按新地图重新选址。倒地救援、付费复活和全队重开沿用现有规则；复活点必须在有效甲板且远离实体，不在活跃登陆坡道上。

## 美术与镜头

延续明亮卡通海面。平台以旧船甲板、修补木板和局部褪色漆带区分区域，避免全图同一种棕色拼格。船体、封闭货棚、商店小棚顶分别作为远处可辨认的地标。

渔网卷、绳圈、薄木片、海草和小贝壳集中在不影响通行的边角；没有看不见的小碰撞。阻挡玩家、螃蟹、钩索或子弹的物件必须有一致且可辨认的规则。图纸默认船体和货棚是实心阻挡，不能只在 Unity 添加 Collider 而让确定性模拟仍可穿过。

靠近镜头的船体／棚顶可能挡住约 1 米高的角色；需验证局部淡化或合适高度。镜头侧淡化只是显示行为，不移除权威碰撞或让子弹穿透。先用少量代表性的立体障碍验证第三人称和俯视画面，再增加细节。

## 后续白盒验证范围

本轮只交付图面与设计。后续实施时，先用甲板、船体、货棚和三处岸口验证空间，鱼、商店及现有 3 只螃蟹进入白盒即可；无需先做一整套新美术。

| 待验证问题 | 条件与观察 | 若失败优先修改 |
|---|---|---|
| 真的能绕行吗 | 1 人和 4 人分别绕船、绕码头，观察是否在同一位置卡住；记录两条路线实际耗时 | 转角净宽、障碍尺寸、连接道位置 |
| 会不会变成空跑大平台 | 3 只螃蟹，保留现有速度；观察玩家是否有明确交火点、换路理由与可见目标 | 压缩外缘、移动实体及岸口，不先堆怪 |
| 出钩时是否有反应余地 | 初始钓竿钓鱼中遭遇登陆，观察预兆识别、收钩完成及被夹时机 | 预兆、登陆朝向和到站位的路线 |
| 能否利用视线换弹 | 初始手枪与 50% 友伤，绕船后换弹；检查穿墙射击、友伤误判和站桩全覆盖 | 阻挡权威数据、交火角度、开口宽度 |
| 钩救是否实际可用 | 4 米初始钩；水槽、外码头和岸角分别落水／倒地 | 站位、边缘碰撞、回钩终点，不假定可跨沟拖岸上队友 |
| 四人是否相互挡死 | 一人拉鱼、一人换弹、一人救援、一人绕路 | 集结区和主路净宽、商店位置 |
| 新地图会不会跳过成长 | 检查第一把钩能触及的鱼、靠近商船的材料消耗及可建区 | 鱼带、商船位置、保留区，避免持续向外推鱼 |
| 视角是否看清来敌与人物 | 第三人称与跟随俯视分别试玩；不拉远镜头囊括全图 | 障碍高度、局部淡化、方向提示与岸口位置 |

新增地图实体、登陆约束、分路状态接入之后，还需做确定性一致性、建造后导航更新、四端联机、全队重开及新存档恢复验证。本轮未运行这些游戏验证，因为没有改动游戏。
