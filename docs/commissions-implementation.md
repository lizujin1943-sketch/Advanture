# 共享委托与团队诱饵实施说明

正式平台接入共享渔业委托。捕获推进、诱饵结算和存档由纯 C# 模拟处理；Unity 显示确认态进度。委托收益独立于个人金币、鱼骨与背包物品。

## 首版规则

以下为可配置的实现者初值；顺序目标的可选澄清尚未收到回复，未视为用户逐项确认。

| 委托 | 任一条件达成即可 | 团队诱饵 |
| --- | --- | --- |
| 1 | 鱼获 6 条，或稀有鱼 2 条 | 1 |
| 2 | 鱼获 10 条，或稀有鱼 3 条 | 1 |
| 3 | 鱼获 14 条，或稀有鱼 4 条 | 1 |

- 委托依次生效，只统计当前目标生效后的捕获。完成一份的鱼不重复计入下一份；不同目标在同一帧成功捕获时按既有确定性顺序结算。
- 普通鱼种与食人鱼均可贡献总鱼获。稀有条件按物种目录的稀有度判定：`fish_06`～`fish_10`；普通／精英／Boss 个体等级不改变物种稀有度。
- 合钓和反向抢钓都按一条成功捕获的鱼计一次，不按获奖人数计数。失败的收益事务、脱钩、挣脱、宝箱、浮木和水怪打断不推进委托。
- 完成自动获得诱饵，不扣个人收入，也没有手动领奖命令。三份全部完成后显示“诱饵已备齐”，进度停止增长。
- 1～4 人共享同一套目标，任何队员均可贡献。既有贡献不会因倒地或退出撤回。
- 保存恢复保留已完成目标和诱饵，不重复发放；新一局清零。未来目标必须为零，诱饵必须等于已完成目标的奖励总和。

## 入口与配置

队伍状态下方的 HUD 显示当前目标、总鱼获／稀有鱼两条替代条件及团队诱饵。面板阻挡鼠标点击向场景穿透；它不修改模拟状态。

`samples/TacticalGame.Unity/Assets/HookIsland/Data/CommissionSettings.asset` 配置目标数组和启用开关，经 `FishingSettings.asset` 绑定。修改后使用 `Tools/Hook Island/Install Fishing Equipment` 重新导出 `PlatformMap.bytes`。未绑定配置时禁用，正式平台已显式启用。最多 16 份目标，每个阈值与每份诱饵奖励均为 1～1000。

主要代码入口：

- `CommissionConfig`、`CommissionState`、`CommissionSystem`：不可变配置、状态及一次捕获的推进规则。
- `HookGame.Cooperative.SettleCatch`：先准备委托草稿，仅在金币、统计、库存和目标捕获成功事务中提交。
- `CommissionStateCodec`：CMS1 快照及完成顺序、计数和诱饵守恒校验。
- `CommissionHud`：共享目标的只读显示。

规则／状态／房间版本为 **18**，输入版本为 **9**，装备地图为 **HIMC**。旧客户端、旧装备地图与旧存档拒绝加载，本轮不提供迁移器。

## 验证

```sh
dotnet run --project tools/HookIsland.Tests -c Release -- --simulation-only --filter=commission_
dotnet run --project tools/HookIsland.Tests -c Release -- --filter=commission_real_udp
python3 scripts/run-island-party.py --app artifacts/commissions/HookPlatform.app --players 4 --commissions
./scripts/verify.sh
```

验收驱动必须显式传入 `--commissions`，仅存在于编辑器／开发构建。它只提交普通移动、出钩和等待输入。原生验收使用近岸鱼群、每份“2 条鱼或 1 条稀有鱼”的三份目标缩短时长；默认 6／10／14 条路线另由单人普通输入完成，共捕获 30 条鱼，得到 3 份诱饵。没有向运行状态注入鱼获、奖励或进度。

原生验收发现建造测试驱动同时启动并覆盖委托输入，已补全开发场景互斥，重新构建后所有客户端均只有一个验收驱动。开发构建成功，零错误，但 Unity 提示一条未编译导入／后处理代码的警告；本次驱动变更已由重新构建后的原生流程验证生效。发布构建零错误、零警告。进度、各阶段完成与最终 HUD 截图已目视核对，日志未发现运行异常。

联机验证限于本机真实 UDP，不等同于跨机器、公网或断线重连验收；正常输入可完成默认目标，也不代表正式地图长期难度与经济已完成平衡。

## 后续边界

诱饵状态已可供后续系统读取；进度事件、终局灯笼巨鱼、胜利与下一局仍属于总目标的未完成项。当前不会自动召来尚未实现的巨物。可上岸鱼／Boss 的上岸移动、战斗和奖励流程仍按用户要求延后设计。
