# 单人自动复活与多人倒地付费

2026-10-23。正式场景 `HookPlatform.unity`，在已有免费救援、个人钱包与原房间重开上调整死亡流程。

## 玩家规则

- 单人血量归零后跳过救援倒计时和窗口：金币足够时自动扣费，回到安全出生区域；不足则当帧游戏失败。
- 多人倒地后显示“立即复活”按钮，可以主动支付个人金币，无须等到最终死亡。原有 60 秒倒地窗口与队友按住 R 3 秒免费救援继续保留。
- 报价在倒地时锁定，沿用 `10 + floor(本局模拟秒数 / 300) × 5 + floor(个人金币 × 10%)`。成功付费后满生命、满耐力，保留装备、背包和饥饿；没有合法落脚点不扣款。
- 免费救起不扣款，清除本次报价；下次倒地重新报价。余额恰好等于费用时可复活。多人仍在全部最终死亡且无人付得起个人费用时失败。

## 实现与边界

`RevivalSystem` 负责倒地报价、免费救援和复活扣费；`HookGame` 在单人死亡转变的同一模拟帧调用已有原子复活事务。多人按钮经 `RevivalController`、`RevivalRequestBuffer` 和正常输入通路提交，界面只读取确认状态。

每次血量归零递增 `DownedId`，`Deaths` 继续记录最终死亡次数。付费请求绑定本次倒地代号和递增请求号；成功与失败都记录回执，重复点击、重发与读档不重复扣款。免费获救后再次倒地也会获得新代号，旧请求不能误付下一次复活。成功提前复活会解除两端拖拽与剩余击退，失败请求则保持原救援状态。

同帧先处理付费输入，再计算免费救援进度；此前已经确认免费获救的请求不扣款。单人按实际入场人数判断，预留空位不计，已入场但离线的队友仍计入多人。离线角色不自动扣费；单人自动复活找不到落脚点时保留金币和死亡状态，之后由玩家主动重试，不隐式重复尝试。

规则／房间协议为 **24**，输入为 **11**，状态为 **23（HISF）**；地图保持 **HIMF**。状态增加倒地代号，旧构建和旧存档明确拒绝混用。通用帧同步核心、传输、重连及存档事务实现均未修改。
