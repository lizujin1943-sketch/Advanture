# 终局灯笼巨鱼与胜利结算实施说明

2026-10-22：完成共享委托后，公共诱饵会召来灯笼巨鱼。玩家在三个不同岸边持续合钩，完成后进入胜利页，并可在原房间由房主带全队开始下一局。巨鱼始终在水中；没有实现用户延后的 Boss 上岸移动、战斗或奖励逻辑。

## 当前规则与初值

- 完成全部配置委托且累计诱饵足够后，自动消耗 3 个公共诱饵，只消费一次。委托累计获得的诱饵与终局已消费数量分别保存；界面显示可用余量。
- 召唤等待 10 秒；巨鱼浮出后，按当前未离线且未最终死亡的角色数要求同时挂钩：1／2／3／4 人分别需要 1／2／2／3 钩。倒地仍计人数，最终死亡减少要求，复活重新计入；零存活者不能获胜。
- 每轮连续保持 5 秒，达标期间全体挂线者合计每秒消耗 12 点耐力并均摊。更多钩只分担耐力，不缩短时长。挂钩不足时，本轮计时归零且不扣牵引耐力；挂着钩仍不能自然恢复耐力。已完成轮次不回退。
- 每轮成功后解除巨鱼钓线并收回空钩；巨鱼潜水 6 秒，再选择另一处合法岸边。三轮优先南、东、北，依照实际平台形状选择可用位置。没有合法水域或可行动的岸上玩家时等待，不额外扣诱饵，也不传送角色。
- 巨鱼身体半径 1.2 m，位置距候选岸边地块中心 3.1 m；站位标记距该中心 0.7 m。初始 3×3 平台和 4 m 钓竿可参与。换位优先间隔至少 4 m，空间不足时仍选择不同的合法位置。浮出身体范围阻挡扩建，潜水后不阻挡。
- 零耐力、倒地、落水、购物、被击退、被拖拽或未装备钓竿时不能加入。主动取消、耗尽、被击退、被拖拽、超出杆长、倒地／死亡和离线立即解除对应钩索；这些失效先于本帧完成判定。
- 巨鱼是独立合钩目标，没有主钓、反向切线、普通捕获收益或重复委托计数。扫掠路径中更近的鱼、玩家或其他可钩目标仍先被命中。
- 三轮完成后，清除所有角色的钓线与拖拽，冻结整个玩法状态和玩法时钟。网络确认帧继续推进，所有客户端显示本局真实鱼获、金币收入、鱼骨收入和用时。当前没有另加终局资源或永久成长奖励。
- 房主“全队开始下一局”沿用重开屏障：保留房间、连接、身份与席位，所有人同步新局初态，旧局消息不能重放。失败重开继续可用，正常游玩中不能重开。

这些数值是实现者给出的可配置初值，不是已经完成的战斗难度或时长平衡结论。

## 配置与接入

正式配置为 `samples/TacticalGame.Unity/Assets/HookIsland/Data/FinaleSettings.asset`，由 `FishingSettings.asset` 引用。可配置启用、诱饵消耗、召唤／潜水／持续合钩时长、共享耐力消耗、各人数门槛、身体半径、岸边距离与换位距离。修改后执行 Unity 菜单 `Tools/Hook Island/Install Fishing Equipment`，导出并刷新 `PlatformMap.bytes`。未绑定或关闭时保留旧场景行为；启用要求地图有平台且配置的委托能提供足够诱饵。

- `FinaleConfig`／`FinaleState` 保存不可变参数和确认状态。
- `FinalePlacement` 用整数坐标进行有界岸边、水域、保留格及边界检查。
- `FinaleSystem` 推进消费、合钩、均摊、换岸和胜利；`FinaleRules` 提供人数与共用空间规则。
- `HookGame.Finale` 在既有命中、敌人、救援与海域帧序中编排，先清除失效线再推进终局。
- `FinaleStateCodec` 校验阶段、计时、消费、位置、线长及目标互斥，拒绝损坏快照。
- `FinalePresentation`／`FinaleHud` 只读确认态，显示巨鱼、灯笼、岸边标记、合钩进度和胜利结果。按钮只提交已有房间操作。

终局接入时规则／状态／房间协议版本 **20**，输入 **9**，装备地图 **HIME**，状态末尾增加 **FIN1**；外围商人接入后，当前规则／状态／房间协议 **21**、输入 **10**、地图 **HIMF**。旧地图、构建与存档明确拒绝，本阶段不迁移旧档。

## 验证入口

```sh
dotnet run --project tools/HookIsland.Tests -c Release -- --simulation-only --filter=finale_
dotnet run --project tools/HookIsland.Tests -c Release -- --filter=finale_real_udp
./scripts/verify-hook-restart.sh network_finale
python3 scripts/run-island-party.py --app artifacts/finale/HookPlatform.app --players 4 --finale
./scripts/verify.sh
```

`--finale` 显式启用开发验收场景，使用缩短的委托与终局计时，通过普通移动、出钩、取消、自然恢复完成委托、三岸合钩、胜利、重开和新局捕鱼；没有运行时注入资源或阶段。自动操作者与其他验收场景互斥，不进入发布程序集。另以正式默认委托、鱼群和终局数值、初始钓竿验证单人可达性；该受控用例关闭敌人，不代表正式战斗和经济已平衡。

验收记录由本阶段的 `artifacts/finale/verification-summary.json` 汇总。后期商人可达路径、晚加入／重连和整体体验仍在总目标中；本子系统完成不能代表完整游戏完成。

- 修复后确定性模拟 276/276；Unity 编辑器 79/79；终局真实 UDP 1／2／4 人通过；重开完整套件 16/16。
- 最新原生 1／2／4 客户端都完成三岸、胜利、原房间重开和新局捕鱼，所有参与者均实际挂钩；各端完整 checkpoint 字节一致。方向距离、钓线、胜利页和房主／客人操作提示已目视检查。开发／发布严格构建均零错误／警告，发布程序集不含自动验收类型。
- 首次全仓库验证退出 1：唯一失败是测试多加了“人人先捕过鱼”的条件。新增晚参与者复现后，改为验证团队委托和全员终局参与，重开全套 16/16 通过。全仓库其他套件通过，结合修复后模拟、编辑器和原生检查形成本阶段证据；没有把原全量命令记作退出 0。
- 四人原生首次尝试有客户端在 Unity 初始化时退出；补充进程日志后同构建重试通过，启动退出根因未确定。所有记录均保留，当前验收限本机 UDP 和受控玩法流程。
