# 宝箱回收、合作搬运与开启

2026-10-22 验收更新。入口为正式平台场景 `samples/TacticalGame.Unity/Assets/HookIsland/Scenes/HookPlatform.unity`。宝箱与鱼分开实现；普通鱼、食人鱼继续使用原有合钓及反向抢钓规则，Boss 上岸流程未做。

## 可操作规则

小宝箱和稀有小箱可由一名玩家出钩回收，拉入有效平台收获区域自动获得金币、木材和鱼骨。稀有箱漂得更快。大宝箱需要至少两根有效钩索才能移动，最早仍连接的玩家决定拉取方向；一根线时原地等待，三四根线不额外加速，不发生反向抢箱。单人房间不生成大箱。

大箱抵岸后固定参与者及主拉者，释放所有钓线。任何可行动的岸上玩家靠近至 1.6 米内，按 **E** 开启；三个奖励分别均分，余数归抵岸时的主拉者。已经退出者、仅帮忙开启者不参与分配。抵岸后某位参与者断线不会改变既定份额；当前房间仍沿用原有断线结束规则，这不代表已经实现重连。

钩箱不额外扣耐力，但占用钓竿、锁定自主移动并停止耐力恢复。取消、击退、倒地、离线、无圈落水、卸竿或超线长解除自己的连接；最早的剩余连接接替主拉，最后一根退出后恢复剩余漂流时间。零耐力仍可钩箱。

每帧先结算伤害、死亡及失效线，再处理抵岸。移动后再次剔除超长线，避免无效成员进入奖励名单。该帧开始移动时有两根线且抵岸时仍至少留有一根线，已完成的抵岸成立。

上述主拉、单人大箱省略、不耗耐力及均分细则属于实现者的首版口径；可选澄清尚无回复，不视为用户逐项确认。

## 同步、事务与职责

- `TreasureMotion` 只负责确定性刷新、漂流与内容抽取；`HookGame.Treasure` 处理连接、搬运、抵岸、开启与结算；不依赖 Unity。
- 开箱命令包含槽位、刷新代次、递增请求编号。成功或失败均产生最终回执，重发同一请求不能重复发奖，旧代次不能开启新箱。失败后需要再次按 E；空间或距离改变不会自动重试旧点击。
- 所有参与者的钱包、统计、材料事务和箱子回收同时提交。材料放不下时落在箱子所在的有效平台。任何账本或实例上限失败都不部分发奖：小箱保持挂线等待，大箱保持关闭。
- `TreasureRequestBuffer` 负责持续提交直至确认，与购物、建造、背包和复活交易互斥；房间设置可与它共存。重开、离房清空缓存和表现。
- `TreasureController` 只排队输入、读取确认态；`TreasurePresentation` 只显示箱子、连接数和 E 提示。商店提示在附近有可开箱时隐藏；成功信息使用现有 HUD 反馈区。
- 当前地图 **HIMB**，规则／状态／房间协议 **17**，输入 **9**；新增快照扩展 **TSR1**。旧地图、旧构建及旧快照明确拒绝，本轮未提供迁移器。

## 验证与复现

确定性模拟 **165/165** 通过，其中宝箱 24 项规则／边界测试及 9 项正常输入场景，覆盖 1／2／4 人与 0／3／6 帧输入延迟。边界包括大箱门槛、接力、击退、抵岸移动后超线长、冻结收益名单、同帧开箱、刷新后旧请求、满包落地、后续参与者统计上限导致整单回滚、漂流刷新、扩建后生成和保存恢复。Unity 编辑器检查 **57/57** 通过；新增测试先复现了未绑定宝箱资产时意外开启的问题，再验证修复。

开发验收使用 `TreasureSmokePilot` 产生正常移动、瞄准、出钩及开箱输入。它只在编辑器／开发构建中存在，必须显式传入 `-island-treasure-smoke 1`；正式场景没有自动游玩组件，不注入运行资源或钓线。场景配置单独检查，验收地图使用较慢的大箱回拉和固定机会，保证可重复观察四根线。

```sh
python3 scripts/run-island-party.py --app artifacts/treasure-chests/HookPlatform.app --players 1 --treasure

python3 scripts/run-island-party.py --app artifacts/treasure-chests/HookPlatform.app --players 4 --treasure
```

本机原生客户端已经完成 1／2／4 人运行，四人场景中四名玩家均参与大箱拉取，房主与所有客户端完整 checkpoint 逐字节一致。完整仓库 `./scripts/verify.sh` 退出 0；最终复核修复后，隔离程序集的钓鱼及真实 UDP 回归 **184/184**，其中宝箱 **36 项**（含 1／2／4 客户端 UDP）。最终开发包再次完成四人验证，日志无运行异常。
