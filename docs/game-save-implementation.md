# 游戏存档接入记录

日期：2026-10-29。范围：HookIsland 当前地图、同版本玩法、本机文件保存与 1～4 人 UDP 房间恢复。通用帧同步核心继续独立于 Unity、Steam 和具体玩法。

## 玩家操作和保存时机

- 房主在 Esc 菜单选择“保存”或“保存并离开”；好友由房主统一保存世界。
- 任意角色仍在出钩／收钩、捕获牵引、钩救、近身救援、近战或击退位移中时，请求等待，不取消玩家动作。菜单可取消等待。
- 自动保存默认每 120 秒一次，由 `IslandFishingController.Saves.cs` 的序列化配置控制；与手动保存采用同一安全条件，各保留一个文件。
- “保存并离开”成功提交后才关闭房间；失败留在房间、保留旧文件并提示。请求等待和文件提交前都不先断开房主自己的客户端。
- 大厅通过“继续 · 手动存档”或“继续 · 自动存档”恢复。默认等待保存时在线的原队友，房主也可提前开始。未返回的人保留原角色，按正常离线规则处理，之后可以返回。

安全存档不等于把世界重置成初态。落水、倒地、鱼游动、敌人冷却、水球飞行和已完成交易都保留实际状态和计时；关闭应用期间不推进游戏时间，不额外恢复生命、耐力或刷新商品。初次加载的表现基线不补播以前的收入提示。

## 分层和数据边界

| 层 | 入口 | 职责 |
| --- | --- | --- |
| 确定性玩法 | `samples/HookIsland.Simulation/Logic/Simulation/HookGame.cs` | 状态、计时、结算回执；恢复首帧把未返回成员置为正常离线状态 |
| 游戏存档格式 | `samples/HookIsland.Network/Persistence/IslandSave.cs`、`IslandSaveCodec.cs` | 已确认检查点、席位归属、保存时间、长度预算、完整性与玩法兼容校验 |
| 文件适配器 | `IslandSaveStore.cs` | 复用 `FileSaveStore`，同目录候选文件、刷新回读、原子替换；失败不先删除旧档 |
| 房间生命周期 | `IslandHost.cs`、`RoomSeatRegistry.cs` | 仅房主确认态可捕获、等待条件、原席位预留、新会话恢复 |
| 本机身份 | `IslandPlayerIdentity.cs` | 保存 32 字节随机本机身份，退出应用后保持角色归属；损坏不静默重建 |
| 本地保存协调 | `IslandSaveCoordinator.cs` | 本机身份、定时请求、等待安全点、文件提交与读取校验；成功提交后才允许离房 |
| Unity 入口 | `IslandFishingController.Saves.cs`、`FishingOverlay.cs` | 序列化配置、菜单和提示，委托保存协调器；不直接修改玩法状态 |

`IslandSaveSafety.IsSafe` 只检查状态，不取消操作或推进模拟。`IslandHost.CaptureSave` 再次校验资格后读取服务器检查点。文件编码层可完整承载状态，正式保存入口通过安全屏障控制捕获时机；网络重连仍使用框架完整快照恢复。

后续职责拆分和确认事件接入见 [确认事件与 Unity 职责拆分](confirmed-presentation-implementation.md)。保存格式和安全条件不变，恢复后的一次性反馈已改为只消费新确认事件。

游戏文件以 `HISV` 标识和版本 1 封装 `FSSV` 检查点，SHA-256 覆盖检查点与席位元数据，文件整体受框架字节预算约束。加载先完成有界读取、校验和验证及孤立模拟恢复验证，然后才创建房间。校验和用于检测损坏，不提供存档防作弊或加密。

读档调用 `CheckpointRestart` 建立新会话 ID、本轮第 0 帧和新输入代数，保留稳定角色 ID、累计游戏时间与确认状态。购买、建造和物品操作的已处理回执随原状态保留；旧连接、旧输入历史和客户端未确认请求不重放。房间协议和玩法规则版本为 29，旧客户端不能混用。

## 文件位置与身份

- Unity 编辑器：仓库内 `artifacts/game-saves/editor/`。
- 发布运行时：`Application.persistentDataPath/HookIslandSaves/`。
- 手动和自动文件分别为 `manual.hisave`、`auto.hisave`；本机身份为 `player.identity`。
- 目录中的 `.lock` 和 `.identity-lock` 是稳定互斥锁文件，句柄关闭即释放，不通过删除锁文件释放锁。

已有角色只能凭原本机身份返回，加入顺序不决定角色归属；未使用席位仍允许新人加入。本轮没有账号和跨机器身份同步，复制世界存档不等于迁移好友身份。通用框架不接触这些游戏身份，也不把私有身份放入发给全体玩家的游戏快照或日志。

## 验证

1. 存档专用无界面测试覆盖：安全屏障不修改世界、完整文件往返、损坏／截断／多余字节拒绝、原子提交失败保留旧档、本机身份跨适配器稳定、已付费购买回执和连击恢复不重复结算。
2. 四客户端真实 UDP 测试覆盖：出钩时拒绝捕获，收杆后保存；不同顺序返回仍恢复各自角色；新会话初态和累计时间与原存档一致；陌生人不能占已有角色，房主可提前开始，原队友之后返回；全端完整检查点一致。
3. Unity EditMode 的 `SaveSceneTests`、`RecoverySceneTests` 和 `FishingCameraViewTests` 合计 25 项通过。包括自动与手动文件分离、损坏文件不创建房间、锁冲突时保存并离开不退出、解除冲突重试成功。
4. `HookPlatform` 实际 Play Mode：通过菜单点击“保存并离开”，确认回大厅且手动文件存在；再点击“继续 · 手动存档”，确认恢复可玩房间且无连接失败。临时检查结束后已退出 Play Mode，未给正式场景加入自动操作组件。
5. `./scripts/verify.sh` 全量回归通过，退出码为 0。包括 HookIsland 398/398 项、背包、角色、落水、敌人、近战、复活及失败重开；四客户端存档恢复保留各自席位和完整检查点。同步最终运行库后，Unity 的上述 25 项测试再次全部通过，控制台无错误。

Unity 验证摘要保存在 `artifacts/game-saves/unity-editmode-results.json`，实际操作产生的临时存档已移到 `artifacts/game-saves/playmode-check/`，不占用玩家正常存档入口。全量回归输出为 `artifacts/game-saves/verify.log`，退出码与套件结果摘要保存在 `artifacts/game-saves/full-verification-result.json`。Unity 使用的模拟、网络、存档与文件适配器四个运行库已逐一核对，与本轮验证构建一致。

## 当前边界

- 只允许在大厅加载，当前场景生成的地图／玩法配置必须与存档一致；不同配置和不兼容版本明确拒绝。暂不提供版本迁移、多槽位列表、云同步或主机迁移。
- 文件提交目前同步执行；小队存档的可用性已验收，尚未做最大世界状态下的磁盘耗时／帧时间压测。
- 验证环境为本机 macOS Unity 2022.3.62f1 和 .NET 8；四客户端使用真实本机 UDP，未据此宣称跨电脑长时间联机、Windows／Linux 文件系统和强制断电恢复已完成验收。
