# 钓竿系统实现

2026-10-21。对应游戏设计中的钓竿、捕鱼耐力、耐力恢复和钓竿商店。入口为 Unity 工程 `samples/TacticalGame.Unity` 的 `Assets/HookIsland/Scenes/HookPlatform.unity`。本模块按正式玩法维护，沿用现有 1～4 人确定性联机；完整背包、其他装备和落水系统继续由各自模块接入。

## 玩法与操作

打开场景后 Play，选择“先自己玩”或创建／加入房间。WASD 移动、鼠标瞄准、左键出钩；右键提前收回或放弃当前鱼。靠近商人按 E 查看商品，按 I 管理自己的钓竿。点击商品查看与当前装备的属性差异，再选择“购买并装备”或“购买放入背包”；点击备用竿可装备，点击右手竿可卸下。Esc 关闭当前面板。

- 初始赠送旧木钓竿：线长 **4 米**、出钩速度 **4 米／秒**、耐力加成 **20**。角色基础耐力 **100**，初始总上限 **120**。
- 线长决定最大抛出距离；出钩速度决定飞行时间。钩子进行连续线段碰撞检测，命中沿途最先遇到的有效鱼、浮木或队友。鱼仍须跃出水面才能钩中。
- 鱼上钩后自动回收，默认 **2 米／秒**。消耗速度为“该鱼每公斤挣脱力 × 实际公斤数 × 普通／精英／Boss 倍率”。倍率依次为 1／2／3。
- 耐力耗尽，鱼挣脱并离开当前钩索，不发金币或鱼骨。消耗与到岸发生在同一帧时先扣耐力，耗尽仍算挣脱。右键放弃同样没有奖励。
- 上岸后金币为 `floor(每公斤单价 × 公斤数) × 倍率`，鱼骨为 `ceil(公斤数) × 2 × 倍率`，都归实际收鱼者。不同玩家不能花对方金币。
- 使用钓竿期间暂停恢复；空钩、钩浮木和拉队友不消耗捕鱼耐力。结束操作后等待 **2 秒**，再以 **5 点／秒** 恢复到上限。剩余耐力不足上限也可继续出钩。
- 换装只改变上限，不补充当前耐力；新上限较低时裁切溢出部分。出钩、回收或被拉期间不能换竿。没有装备钓竿时不能出钩，但可恢复角色基础耐力。

十种鱼采用配置表中的稀有度、单价和每公斤挣脱力；重量为 1～10 kg，以 0.1 kg 为步长。鱼的体型随重量变化，物种使用不同颜色与轮廓，精英／Boss 有等级色彩提示。近岸鱼群定期提供普通轻鱼，保证初始竿有可完成的捕鱼目标。

## 商店与收纳

共有 **31 支钓竿**：1 支赠送竿，以及 T1～T5 每级 6 种售卖竿。六种取向为远投、快钩、强韧、迅远、长韧和均衡。当前平台商人默认为 M1，仅售 T1；M2～M5 的出货等级概率按设计表实现，正式平台已配置外围补给船，玩家扩建到达后购物，见 [外围商人实施说明](merchant-routes-implementation.md)。

商店使用 8×6 陈列格，商品具有不同占格尺寸。库存全队共享，一件商品只能被一人买走；售罄位置保留，到默认 **600 秒**时整批重抽，包括未售商品。点击时携带商品批次，补货后原选择失效，不会替玩家购买新商品。

本模块提供 Lv.1 的 4×4 钓竿收纳空间，自动寻找空位并允许旋转。购买并装备时，旧竿保留并回到包内；从背包装备新竿时，其腾出的空间可放旧竿。所有布局检查完成后才一并提交物品、库存、钱包和装备变化。空间不足时不扣款、不清空商品，也不丢弃旧竿。

商人交互检查当前已建平台及 3 米距离，新增地块也可作为购物站位。打开商店获得同步的购物拉拽保护。购物、装备和建造面板相互切换时关闭前一面板，世界继续运行。

完整材料占格、背包升级、整理和物品转移属于独立背包模块；本模块的收纳事务及物品身份已提供接入边界，不能再建立第二份权威钓竿库存。

## 配置入口

| 文件 | 可配置内容 |
| --- | --- |
| `samples/HookIsland.Simulation/Data/rods.csv` | 钓竿 ID、名称、等级、线长毫米、出钩毫米／秒、耐力加成、价格、占格宽高 |
| `samples/HookIsland.Simulation/Data/fish.csv` | 鱼种 ID、名称、出现权重、每公斤单价、每公斤挣脱力千分值 |
| `Assets/HookIsland/Data/FishingSettings.asset` | 角色基础耐力、恢复等待秒数、每秒恢复量、收鱼速度、商人等级、补货秒数、世界种子 |
| `Assets/HookIsland/Data/PlatformSettings.asset` | 引用上述钓鱼配置，并保留平台配方与地块配置 |

`Assets/` 路径相对于 Unity 工程。CSV 编译为模拟程序集资源，修改后运行 `./scripts/sync-hook-island.sh`，再刷新 Unity；配置资产在新建房间时转换为不可变规则。保存的 `PlatformMap.bytes` 通过 `HookPlatformSceneBuilder.InstallFishingEquipment` 更新，场景实际读取 `PlatformSettings`。参与联机的客户端必须使用相同规则和配置表，兼容性校验会拒绝不匹配的客户端。

## 实现职责与联机

| 模块 | 职责 |
| --- | --- |
| `FishingCatalog` / `FishingConfig` | 不可变定义、配置和统一查询；增添同类钓竿通过表数据扩展 |
| `StaminaSystem` | 整数耐力消费、恢复等待、恢复速度与上限 |
| `GridInventory` | 与物品类型无关的格子放置、旋转和重叠检测 |
| `RodShop` | 可重放的共享商品生成与等级概率 |
| `RodEquipmentSystem` | 个人购买／收纳／装备事务与请求回执 |
| `FishingStateCodec` | 装备、鱼属性、耐力和商品批次的快照读写及不变量验证 |
| `RodRequestBuffer` | 保持同一操作请求直到收到权威回执；重试不会重复消费 |
| `FishingEquipmentController` | Unity 的面板状态、操作意图和结果提示 |
| `FishingEquipmentOverlay` / `FishingPresentation` | 属性比较、装备和耐力界面、鱼与钓竿外观；不修改权威状态 |

模拟以 30 Hz 运行，坐标为整数毫米；30,000 内部单位表示 1 点耐力，以保持消耗与恢复精确、可重放。`HookGame` 协调已有移动、钩索和各服务，帧同步核心没有引入 Unity 或钓鱼依赖。职责通过组合划分，无需为不同钓竿建立行为重复的继承树。

同帧抢商品按同步的玩家槽位顺序结算；失败和成功都保存回执。快照包含个人余额和累计收入、物品身份及归属、货架、补货时钟、鱼种重量等级、钩索进度、当前耐力及恢复等待。恢复时验证布局、归属和收支守恒。当前房间协议版本 6、规则版本 6、输入版本 5（40 字节）、状态版本 6，不与旧构建混用。

`Fisher.Coins` 为个人当前余额；`Fisher.CoinsEarned` 为累计收入；`HookState.Coins` 仅为个人余额总计，不能用作购买资金。旧 `HookIsland.unity` 保留旧岛屿规则，正式平台以本页规则为准。
