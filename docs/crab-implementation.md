# 螃蟹：主动登岸、夹击与攻击者奖励

2026-11-01。按本次确认方案实现第一个岸上敌人，正式入口仍为 `samples/TacticalGame.Unity/Assets/HookIsland/Scenes/HookPlatform.unity`。

## 玩法

2026-11-03 调整：正式地图暂停水怪生成，食人鱼保留。开局 10 秒后开始生成螃蟹，默认同时最多 3 只，首轮每隔 3 秒生成一只。每只从不同岸线起点寻找有效登岸位置，播放 1.5 秒爬岸预警，再追击玩家。没有水中游动或钓上岸阶段；各自击败并成功结算后等待 60 秒刷新。没有有效登岸点则每秒重试。数量（1～8）和首轮间隔进入地图配置。

追击速度 2 米/秒。12 米内选最近、可达、在线、未倒地或死亡的岸上玩家，同距按槽位决定。购物不提供免疫；不会下水追人。无目标满 3 秒后走向可达岸边退场，途中重新发现目标可恢复追击。退场不发奖励，之后重新等待 60 秒。

距离目标 1.2 米且无遮挡时停步举钳，锁定方向前摇 0.6 秒，随后对前方 1.4 米、90°扇形判定一次。每个有效目标最多受到一次 12 点原伤害和 0.5 米击退；防御采用已有公式。夹击表现 0.2 秒，收势 1 秒。取消了冲撞、撞墙翻身与翻身增伤。

螃蟹 100 点生命。平底锅每次 25 点，沙漠之鹰每次 35 点；枪弹只命中射线最近的实体，不穿透活螃蟹。普通受击不硬直，致死伤害取消尚未执行的攻击。钩索只在举钳前摇且不受保护时打断，使其进入 1 秒收势并获得 3 秒打断保护；不会扣血、牵引或计为有效攻击者。钩索打断与水怪一样清除该次捕鱼连击；武器击败不增加或清除捕鱼连击。

只给该刷新代次内造成过实际伤害的攻击者发奖。伤害占比和最后一击不影响分配，挥空、钩索打断及攻击尸体不计入。攻击者后来倒地、死亡、离线仍保留资格。

每人金币为 `round(100 / n^0.6)`，1／2／3／4 位攻击者分别获得 **100／66／52／44 金币**，每人另获 **2 鱼骨**。公式固定为整数表，避免浮点幂与舍入进入跨平台模拟。奖励不受捕鱼连击加成，不推进鱼获委托。

## 代码与数据边界

- `samples/HookIsland.Simulation/Data/Configuration/CrabConfig.cs`：可配置时长、生命、速度、伤害、击退及固定奖励表。`FishingConfig.Crabs` 默认关闭，正式 Unity 配置显式启用；启用时要求存在平台与近战系统。
- `Data/State/CrabState.cs`：值类型快照，保存刷新代次、攻击序号、位置、方向、阶段与剩余帧、导航目标、无目标计时、打断保护、攻击者位图和发奖回执。
- `Logic/Combat/CrabNavigation.cs`：从平台生成间距 0.5 米的四邻接导航图，最多 512×16 个候选点。节点、邻接、岸线候选均按固定顺序处理。查询采用有界广度优先搜索，路径段检查完整身体占地；攻击线另行检查地面与实体障碍，允许攻击站在有效平台边缘的玩家。地图只允许新增地块，地块数量变化时重建缓存；恢复模拟重新创建缓存。
- `Logic/Combat/CrabSystem.cs`：固定优先级与计时状态机。等待、爬岸、追击、前摇、夹击、收势、退场与死亡分开；夹击只在穿过命中帧时交付伤害。导航通常每 6 帧重新选择最近可达目标，不使用 Unity NavMesh、物理或浮点逻辑。
- `Logic/Simulation/HookGame.Crabs.cs`：按稳定数组索引管理多只螃蟹，同帧所有近战和枪击完成后逐只结算奖励，避免写回旧玩家副本覆盖钱包。各自的血量、贡献和发奖回执互不串用。钩索先于前摇推进，最后一帧前摇仍可被打断。复用 `ApplyEnemyHit`、个人金币和 `InventorySystem.CreditMaterials`。
- `Serialization/CrabStateCodec.cs`：完整状态编码与阶段、范围、方向、成员资格、回执校验；恢复额外检查螃蟹处于有效平台上。

上面未重复根路径的文件均位于 `samples/HookIsland.Simulation/`。通用帧同步、网络运输和文件保存事务没有加入螃蟹专用分支。

## 奖励事务与恢复

致死时固定有效攻击者位图，停止攻击，进入待发奖的死亡状态。结算先检查所有个人钱包、累计收入、材料收入及全局金币上限，再通过同一个库存事务向全部攻击者入账。背包放不下的鱼骨沿用地面材料包；成功后统一增加个人金币及材料账本，设置 `Rewarded` 回执。

如果全局材料实例或金额上限使整笔奖励无法提交，保留死亡与待偿记录，不发部分奖励、不开始刷新，后续有容量时再提交一次内部待偿奖励。此机制不重放用户已经失败的购买、建造或其他交易请求。

参与者以房间稳定席位记录，离线不删除资格；已入场席位不能被另一身份替换，读档重开沿用原席位映射。重连和保存保留血量、动作进度、攻击者与发奖回执。游戏关闭期间不补算时间。新刷新代次清空贡献记录，退场不带走已结算的玩家收入。

当前规则版本 **34**，状态版本 **31**，输入格式 **13**；装备地图标识 `0x4B4D4948`，状态标识 `0x4B534948`。`CRB2` 保存固定数量的螃蟹状态，`MEL2` 增加食人鱼待结算击杀记录。按用户要求只保证新存档，不迁移旧档。CSV 在读取时统一为 LF 后计算摘要，避免 Windows CRLF 与 macOS LF 产生不同兼容摘要。

## Unity 与 Blender

正式配置是 `Assets/HookIsland/Data/CrabSettings.asset`，由 `FishingSettings.asset` 引用。启用开关、数量、首轮间隔及首刷、刷新、生命、速度、前摇、收势、伤害、击退、爬岸和打断保护可在 Inspector 调整；修改后新建房间生效。共享地图配置进入会话校验。Unity 每只螃蟹持有独立视图，位置、动画、预警与生命条只读取对应确认状态。

模型源文件：`samples/HookIsland/Blender/Crab/shore_crab.blend`。Unity 导出：`Assets/HookIsland/Resources/Enemies/ShoreCrab.fbx`。原创低多边形模型约 1300 三角面，蟹壳、眼柄、八条腿、两只蟹钳和四个钳指独立组织；14 个动作关节。重新生成命令：

```sh
blender --background --factory-startup --python scripts/blender/create_crab.py
```

`CrabPresentation` 读取确认态，播放爬岸、行走、举钳、夹击、收势及死亡，显示攻击扇形和生命条。不会通过碰撞器、动画事件或脚本直接修改模拟。确认金币和材料事件沿用现有反馈通道。退场或房间重开时清理表现。

显式编辑器校验入口为 `Advanture.HookIsland.Editor.CrabValidation.Run`，会检查正式配置、地图往返、模型关节及无碰撞器，并将六个阶段渲染到 `artifacts/crabs/`。仅在 Editor 编译，不挂载正式场景，不进入发布构建。
