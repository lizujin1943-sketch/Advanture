# 拉鱼时慢速移动

2026-10-23：用户要求上鱼时可缓慢移动，初值为正常速度的 30%。这里按已钩住鱼、正在回拉处理，普通鱼与食人鱼一致。

## 规则与实现

- 单人和合钓每位仍挂线的玩家都可以移动，比例取自身当前速度的 30%；默认岸上 3 m/s → 0.9 m/s。装备属性与泳圈先计入正常速度，再施加比例。
- 拉鱼速度、均摊耐力与最终收益规则不变；边游泳边拉鱼会同时支付两种耐力，耗尽仍脱钩。继续使用原有整数位移及余量保存。
- 空钩飞行、空钩返回、浮木、宝箱、拉队友和终局巨物保持原移动锁定。取消或被切线后，空钩收回才恢复正常移动。
- 走出平台正常落水；线长超限正常断开。倒地、离线、购物、被拖拽和受击退的主动移动限制仍优先生效。
- `CharacterMovement.HookSpeedPermille` 是挂钩状态对应移速比例的唯一入口，`ReelingSpeedPermille = 300` 是当前初值。`HookGame.Step` 在权威模拟及预测中使用同一规则，Unity 继续提交原始方向输入，不再二次缩放；角色面板从确认态读取同一比例。
- 规则兼容版本及房间协议升为 23，防止新旧移动规则混联；状态格式 22、输入格式 10、HIMF 地图格式保持兼容布局。旧规则 checkpoint 仍由兼容清单拒绝，未提供迁移。

Unity 回归发现已有镜头测试将表现对象挂在镜头自身下面，切换镜头时会一起移动，断言结果因帧间隔和 Game 窗口画幅而变化。测试改为镜头与表现对象共用独立根节点，并固定 16:9；未调整生产镜头或表现代码。初次失败、仅固定画幅的失败及最终通过记录均保留在上述目录。

网络测试使用本机回环 UDP；四客户端场景中两位垂钓、两位旁观，四人同时垂钓移动另由确定性测试覆盖。未验证跨电脑网络及人工操作手感；未运行全仓库 `./scripts/verify.sh`，因为本次未改传输、重连或存档事务实现。
