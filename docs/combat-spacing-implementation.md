# 战斗单位占位与螃蟹朝向

2026-11-04：单位占位由纯 C# 权威模拟在每帧末统一分离；Unity 只读取结果，不使用 PhysX 决定站位。

## 螃蟹倒向的根因

实际 `ShoreCrab.fbx` 中，双眼的源坐标 Y 为 -0.280 m，嘴为 -0.325 m，双钳关节为 -0.200 m；FBX 根节点包含 X=-90° 的轴转换，Unity 导入启用了 `bakeAxisConversion`。模型正面不能直接当成逻辑根节点的 +Z。原表现层直接保留导入旋转，而移动、夹击扇区和击退都沿权威 `DirectionX/Z`，因而出现模型背向移动和攻击。

`CrabPresentation` 在创建时从实际导入资源的双眼中心相对蟹壳测量前向，只为模型子层计算绕竖轴的校准角。逻辑根节点、预警扇区、攻击方向和伤害判定不变；走路、蓄力、夹击和收招共用这份校准。`CrabPresentationTests` 直接检查实际 FBX 的双眼与预警在四个朝向上的一致性及模型正立情况。

## 占位规则与确定性

- 玩家使用 330 mm 半径，螃蟹 400 mm，食人鱼 250 mm，与现有战斗命中体积一致。玩家、螃蟹、食人鱼按固定种类区间和槽位组成稳定 ID。
- 地面与水下分层：甲板上的玩家和螃蟹互相避让；游泳玩家与食人鱼互相避让；食人鱼不会隔着甲板推动陆上玩家。
- 等待加入、已死亡玩家、死亡或离场螃蟹，以及被钩住、逃逸、待刷新的鱼不参与普通活体分离。倒地、离线和被拖拽玩家作为固定占位。登岸螃蟹可以调整落点，水中登岸起点保持不变。
- 蓄力中的水怪和活动 BOSS 本体作为固定障碍。BOSS 使用本体椭球的保守水平圆包围，触手继续作为攻击轨迹，不变成随动画移动的墙。
- `HookGame.ResolveCombatSpacing()` 在普通 `Step` 的 `AdvanceFinale()` 之后执行一次，涵盖主动移动、AI、击退、拖拽、地形破坏和复活的最终位置。现有确认态、预测态和回滚执行同一规则。
- 算法只使用整数运算。所有候选按稳定 ID 排序，同心单位也只根据 ID 选择分离轴；不使用随机数、浮点方向或字典遍历顺序决定结果。正在击退的玩家同步平移其轨迹原点，方向、已走距离和命中回执保持不变。

## 成本和地形边界

`CombatSpacing` 使用 1 m 空间哈希，将圆盘的包围盒放入覆盖的桶，只查询相交桶中的单位，去重后再作圆盘窄相位检查。移动后立即更新桶；桶、候选数组与地格哈希复用容量，缓存不进入检查点。稀疏 1600 单位测试产生 **0 个窄相位候选**，全量两两方案需检查 **1,279,200 对**。

每帧最多 12 轮约束投影，单次修正最多 400 mm。玩家和水下敌人按不超过 50 mm 间距检查整段位移，螃蟹复用原导航的 100 mm 路径检查；被挡住的一侧将剩余修正交给另一侧。两侧法线都被挡住时，按固定顺序尝试切向和反切向滑动，避免有纵向空间的狭道永久卡在横向重叠；滑动仍执行相同路径检查，禁止跳过墙体。平台占地使用共享地格哈希，分离不会把陆上单位挤入水里，也不会把游泳玩家挤上甲板。

这是有界位置修正：极端密集、没有足够合法空间或两个固定对象本来重合时，优先守住地形和固定对象，允许暂留残余重叠。局部密集接触仍可能产生局部平方成本。此系统处理帧末占位，不代替高速单位之间的连续碰撞检测，也不修改原有攻击命中方向。
