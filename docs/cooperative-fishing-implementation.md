# 合钓与反向抢钓实施说明

2026-10-21：正式装备模式的普通鱼和食人鱼接入多根钓线。方向、耐力、主钓交接、移动与奖励由纯 C# 确定性模拟处理，Unity 读取结果并显示每人的钓线、耐力及主钓／辅助身份。

## 已实现规则

- 第一根有效线成为主钓。新钩命中时以鱼为顶点比较水平向量：≤90° 辅助原主钓，>90° 原子切断旧线并成为唯一主钓。零耐力或目标超出本竿线长时不能加入或抢钓，即使钩尖擦到鱼的碰撞范围也不会切断旧线；空钩回收后可再次出钩，没有额外抢钓保护时间。
- 同鱼每秒耐力总消耗沿用鱼种、重量和等级规则，仍挂线者均摊；用十二分之一最小耐力单位保存余量，三人分摊也不会逐帧丢失小数。每条鱼每帧只推进一次。
- 默认每增加一人加速 50%，1／2／3／4 人为 1／1.5／2／2.5 倍。默认单人回拉 2 m/s，对应 2／3／4／5 m/s；速度加成不放大每秒总耐力消耗。
- 任意线退出后，从剩余有效线中按当前耐力点数选主钓；并列保留原主钓，否则取最早加入者。换主钓后清除与新方向 >90° 的旧线。仅牵引移动导致角度变大时保留连接。
- 耗尽、主动取消、超线长、受击退、无圈落水、倒地、离线均退出；受击退者无论夹角都立即脱钩。重连不恢复已断线。有圈水中玩家可以继续钓，但鱼只到水中玩家身边不结算。
- 最后一根线退出才触发既有挣脱动画。食人鱼有任意挂线时不会恢复巡游或咬击；捕获只安排一次刷新。
- 救援钩优先：已挂线鱼与其水中参与者距离不超过 0.55 m，且出钩瞄准该玩家身体范围时，鱼避让这次钩子，仍按原规则命中和救起玩家。普通鱼和食人鱼一致，避免被钓鱼的碰撞体遮挡落水救援；分离的鱼仍可正常合钓或抢钓。
- 普通鱼沿牵引路径进入有效平台收获区域即捕获，不必到玩家身体。先清理当帧失效线，再冻结最终分配名单。金币和鱼骨分别按人数整除，全部余数给当时主钓；已经退出者无奖励，临近抵岸才加入者仍有份额。
- 多人的金币、统计、背包入账和鱼的移除／刷新作为一次结算提交。任意参与者账本或库存达到上限时整笔不提交。背包容量不足的鱼骨落在捕获平台上，水中辅助者也不会把溢出材料生成在海里。

## 配置和代码入口

`samples/TacticalGame.Unity/Assets/HookIsland/Data/FishingSettings.asset` 的 `additionalAnglerSpeedBonus` 默认 `0.5`；对应 `FishingConfig.CooperativeSpeedBonusPermille = 500`，合法范围 0～3000（每增加一人加 0%～300%）。修改配置后使用 `Tools/Hook Island/Install Fishing Equipment` 重新导出 `PlatformMap.bytes`；同房间配置必须一致。

- `CooperativeFishing.cs`：角度、人数、加速、分摊和收益计算。
- `HookGame.Cooperative.cs`：加入／抢钓、退出与交接、按目标推进、抵岸及结算。
- `InventorySystem.CreditMaterials`：多人材料批量事务。
- `CooperativeFishingStateCodec.cs`：COP1 连接顺序和小数余量；校验主钓归属、连接位置及唯一连续顺序。
- `ReelingStaminaOverlay`：只读主钓／辅助人数提示；不修改权威状态。

同帧成员退出与玩家动作先于新钩命中；动作与新命中分别按槽位顺序处理，同帧多次取消会逐次产生交接，不按一批取消合并。所有参与者先支付同一帧的份额，耗尽者退出后再移动和结算。水球处理在牵引之后，命中立即断开受击退者的线。该顺序由各端执行同一份模拟代码保证。

合钓引入时，规则版本、状态版本和房间协议更新为 **15**，输入版本为 **7**，装备地图标识从 HIM9 升至 **HIMA**，合钓快照增加 **COP1**。后续功能扩展后，当前规则／状态／房间版本为 **21**、输入版本为 **10**、地图标识为 **HIMF**。旧客户端、旧装备地图和旧存档明确拒绝；本轮没有旧存档迁移器。有效新存档保留主钓、顺序、耐力余量、鱼状态和已完成结算，恢复不重新发奖。
