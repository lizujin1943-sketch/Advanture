# 阶段 D：正式存档文件层

日期：2026-10-15。本文记录独立存档编码与文件适配的实现及实测范围。会话重开、保存后关房和跨进程继续运行由会话层及验收工具集成；本文件层本身不创建新会话。

## 职责与依赖

- `FrameSync.Persistence`：纯 C# `netstandard2.1` 库，依赖 Runtime；提供 `SaveDocument`、`SaveCodec`、`ISaveStore`、`SaveService`。
- `FrameSync.Storage.FileSystem`：单独的 `netstandard2.1` 适配器，提供 `FileSaveStore`，只有这里使用文件路径和文件系统 API。
- `FrameSync.Persistence.Tests`：`net8.0` 控制台测试，不使用外部 NuGet。行为测试自身运行在正式仓库下，并将临时产物限制在 `artifacts/initial-core/persistence-tests/` 的独占目录中，测试结束后清理。

核心不依赖 Unity、Steam、游戏模型、系统时间或文件路径。存档 UUID 由宿主分配；覆盖同一存档时可以复用 UUID，它与检查点中的会话 UUID 各自独立。

## 使用边界

```csharp
var service = new SaveService(new FileSaveStore(savePath), limits);
SaveDocument saved = service.Save(saveId, server.CaptureCheckpoint());
SaveDocument loaded = service.Load();
```

`SaveService.Save(Guid, Checkpoint)` 先完成编码和一次完整解码验证，再调用 `ISaveStore.WriteAtomic`。正常返回表示存储提交成功；异常会直接返回宿主，宿主可以保持房间运行并重试。不能在保存失败后当作已保存而关闭会话。

“只存确认状态”由调用边界保证：传入服务器或客户端确认状态的检查点。普通 `Checkpoint` 不携带确认/预测标签，存档服务无法从对象内容反推其来源，也不会擅自访问 Sessions。`Load()` 仅返回已校验候选数据，不修改当前模拟；游戏兼容性、游戏状态格式以及新会话重开规则由运行器和会话层继续验证。

`ISaveStore.Read(int maxBytes)` 必须在分配完整读取缓冲区之前拒绝过大文件。`WriteAtomic(ReadOnlySpan<byte>, int maxBytes)` 必须整体提交，不得先清空或删除旧存档。`SaveService` 给读写都传入同一个总字节预算，并对外部适配器返回的字节再次做容量和格式检查。

## 当前二进制格式

外壳格式版本为 **1**。它嵌入当前 `CheckpointCodec` 的完整字节，当前检查点格式已经支持成员状态；存档层不重排或解释其中字段。外壳和内层检查点分别校验，只有两层均有效才返回存档。

| 字节位置 | 内容 | 约束 |
| --- | --- | --- |
| 0～3 | ASCII `FSSV` | 正式存档标识 |
| 4～5 | 外壳版本 | 无符号 16 位小端，当前仅接受 1 |
| 6～21 | 存档 UUID | .NET 固定字节排列，禁止空 UUID |
| 22～25 | 检查点字节数 | 无符号 32 位小端，必须恰好等于剩余正文长度 |
| 26 起 | 完整检查点 | 交给 `CheckpointCodec.Decode` 校验 |
| 最后 32 字节 | SHA-256 | 覆盖自身以外的所有字节，包括身份和版本 |

固定开销为 58 字节，默认总上限为 `8 MiB + 58`。调用方可提供 `RuntimeLimits`，同时约束检查点的实际长度和其声明的六项运行容量。上限相加使用宽整数，结果收紧到 `int.MaxValue`，不允许溢出后绕过检查。预算约束单份编码和读取，不代表整个操作只会分配一份缓冲区。

损坏摘要、截断、尾随字节、伪造长度、空 UUID、超限及未知格式版本都以 `InvalidDataException` 拒绝。参数错误和保存时配置超过预算则在接触存储前失败。SHA-256 用于完整性检查，不提供加密、身份认证、抗恶意修改或旧版迁移。

## 文件提交过程

1. 将保存路径规范化为绝对路径，取得稳定的 `目标路径.lock` 文件独占句柄。
2. 在同目录使用唯一名称和 `CreateNew` 创建候选文件。
3. 写入完整字节并执行 `Flush(true)`，然后关闭写句柄。
4. 重新打开候选文件，先检查大小，再读回并逐字节比较。
5. 目标已存在时调用 `File.Replace`；首次保存调用不覆盖已有目标的 `File.Move`。
6. 提交前失败时只尝试删除本次成功创建的候选文件，保留正式旧文件。清理错误不掩盖原始失败。

没有先删旧文件的步骤，也不在原子替换不受支持时回退到删除加移动。保存目录必须由宿主事先创建。进程中断可能留下候选文件，由宿主按维护策略处理；适配器不会遍历和删除其他进程的候选文件。

锁冲突立即以 `IOException` 拒绝。稳定锁文件长期保留，但锁只由活跃句柄持有，关闭句柄或进程退出即释放；不删除锁文件，防止并发操作分别锁住删除前后的两个文件。该约定覆盖本进程和采用同一适配器的其他进程；宿主必须统一每个保存位置的路径，符号链接、硬链接、大小写别名及绕过约定的外部写入不在保护范围内。

读取不持有写锁，文件句柄允许原子替换，因此提交前读到完整旧数据，提交后新打开的读取获得完整新数据。读取期间观察到长度变化会拒绝返回。文件刷新和替换保证当前操作的完整性；未实现额外目录 fsync，也没有宣称所有文件系统在突然断电后都保留最新替换结果。

## 已完成的行为验证

独立测试共 23 项，按“先失败、再实现、再通过”完成三个阶段：存档外壳 9 项、存档服务 6 项、文件适配 8 项。

- 检查点完整往返，包括保存身份、帧号、累计帧、游戏状态、输入历史、缺失计数和初始化字节。
- 身份、载荷和摘要损坏；截断和尾随内容；摘要正确但版本、长度或内部检查点错误；读取/编码预算拒绝。
- 服务保存前验证、拒绝坏档、向存储传递准确预算，并防御不遵守预算的外部存储实现。
- 真实文件首次创建和覆盖、超限读取在完整缓冲区分配前失败、超限写入保留旧内容。
- 在候选文件完整写好之后注入原子提交异常，确认旧存档仍可读取；首次提交失败不留下部分正式存档。
- 同进程规范化同路径写入冲突、其他路径独立保存、提交前仍能读取旧文件。
- 独立进程持有 `.lock` 时写入被拒绝；进程释放后可以再次写入；普通成功和失败不遗留候选文件。

```sh
/usr/local/share/dotnet/dotnet run --project framework/tests/FrameSync.Persistence.Tests/FrameSync.Persistence.Tests.csproj --configuration Release
```
