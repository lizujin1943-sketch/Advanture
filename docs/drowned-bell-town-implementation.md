# 沉钟镇实现范围

沉钟镇是水陆结合、以探索和枪械战斗为主的独立地图模式。批准设计见 [小镇设计](superpowers/specs/2026-11-05-drowned-bell-town-design.md)、[关底与战场](superpowers/specs/2026-11-05-drowned-bell-town-octopus-finale-design.md)。

## 权威玩法

`IslandMap.CreateTown()` 创建160×128米地图，`TownLayout` 统一提供路面、建筑、门洞、掩体、区域和出怪口。游泳、枪线遮挡、手雷、寻路和角色碰撞使用相同地形；Unity 表现不决定可通行区域。镇区寻路缓存只保存最多八张不可变地形图，不包含单位状态。

十二种建筑沿探索路线分布：归航码头、军火铺、诊所、船具店、工坊、委托所、当铺、测绘站、机房、驿站、档案馆、礼拜堂。诊所、档案馆和礼拜堂可进入，其余以门口服务为主。金币支付和产出在一个权威事务中完成，成功与失败请求均保存回执，恢复快照不重复购买、发奖或维修。

镇模式使用金币，关闭木材、鱼骨、漂流物和自由铺地。首版开局为300金币，是待调优数值。商店提供有限弹药、AK47、泳圈、治疗和手雷；保留基础手枪、近战和背包。两个付费捷径和战场木带维修均可跳过，三个必要目标和返程桥免费。原平台模式保留自己的规则。

六个探索战区使用固定身份的十五只成年敌人和四个幼体槽位。成年种类来自已实现的十种异怪，本镇使用其中九种；追加二十种仍是条件候选，没有作为已实现内容。固定出入口要求距所有在线玩家至少八米并有遮挡，出场和恢复有45帧预警，同屏最多四个成年敌人和四个幼体，最多两个战区同时活动。离开12秒后暂停，保存生命、死亡、奖励和召唤额度；重入不重新发奖或补满血。

## 大章鱼终局

C货场供电、E机房潮闸、F档案三个免费目标完成后，全体在线清醒玩家在祭港就位才能开战。开战冻结本次队伍和人数。大章鱼有四条攻击腕和四条独立受击支撑腕，包含锁定下砸、局部横扫、墨区、断腕和低血量狂暴。攻击调度同时验证危险时序、实际步行速度、墨区减速和未来毁板后的可达安全路线。

直径44米场地保留连续外石环、南侧石尖台和救援落岸；可毁地形仅四条木带的十六个指定板段。维修验证当前尝试和危险状态，以金币恢复指定木带。失败10秒后恢复战场，倒地参战成员免费返回祭火，可以零金币再次尝试；普通街区倒地仍沿用付费复活。

每次尝试的基础手枪专用弹池为单人168发、双人各126发、三或四人各112发。专用弹不占背包，追踪已装入弹匣的来源，离开战场或尝试结束时回收，保留玩家自购弹药。离场再入不补发，同一请求重试不增加弹药。正式镇区每人保留一把基础手枪；扩展或恢复数据中若有额外基础手枪，同一时刻只允许一把枪装专用弹，其他枪可用自购弹，避免覆盖原来源记录。

本体归零后停止伤害，经过六秒死亡表现再一次性向贡献者各发600金币、记录终局完成并生成免费返程桥。此时可继续探索；所有在线玩家到码头确认返航后才结束本轮。

## 保存与兼容边界

规则、输入和状态版本分别为44、18、39，库存格式为BAG7，异怪格式为EDR2，镇区格式为TWN2，Boss内部格式为AWS2。新旧版本不能混联，旧格式快照明确拒绝。状态校验包含金币、装备售出价值、历史枪弹、外部弹、区清理、三目标、付费桥和毁板记录的一致性。

帧同步核心未引入Unity或具体玩法依赖，镇区规则位于 `samples/HookIsland.Simulation`，命令交付位于 `samples/HookIsland.Network`。测试构造和自动验证不会作为正式场景常驻组件。

## Blender 场景美术

建筑与环境现使用独立的 Blender 美术资源，源文件、预览图和复建步骤见 [沉钟镇美术说明](../source-assets/environments/drowned-bell-town/README.md)。新增石木街屋、钟塔、测绘亭、机房烟囱、货垛、石砌岸基与远景遗迹；全部建筑占地、入口、掩体和木带坐标来自现有 `TownLayout`。

`TownArtLayoutExporter` 导出布局，Blender 脚本生成 FBX 与清单，`TownArtInstaller` 检查布局指纹和坐标轴后绑定材质并安装 `DrownedBellTownArt.prefab`。正式场景生成器也会安装该预制件。旧方块的 Renderer 隐藏，原始权威地面资源仍可用于几何回归；动态木桥由确认状态独立驱动。地图美术不包含 Unity Collider。

本轮美术验证使用 macOS Unity 2022.3.62f1：编译与导入成功、完成四张 Unity 场景预览，并通过 2 项导入美术测试与 6 项原有镇区表现测试。测试包括真实 FBX 网格的三个门洞、16 个木带缺口、中心水域以及动态桥的移除/恢复。未复跑网络全量验证，也未将静态预览作为多人实机游玩或通关证据。仓库原有 Unity 版本配置保留。

## 验证边界

专项入口为 `./scripts/verify-hook-town.sh` 与 `./scripts/verify-hook-eldritch.sh`，完整入口为 `./scripts/verify.sh`。镇区测试覆盖无木板可达路线、隐蔽出怪口、价格和去重、有限弹来源、全员准备、零金币重试、真实枪击关底结算、返桥归航，以及四个真实UDP客户端与保存恢复一致性。

正式入口是 `samples/TacticalGame.Unity/Assets/HookIsland/Scenes/DrownedBellTown.unity`，已设为Build Settings的第一启用场景。打开该场景进入Play后创建房间即可试玩；E与建筑、免费目标、祭火和维修点交互。编辑器菜单 `Tools/Hook Island/Create Drowned Bell Town` 可从权威几何重新生成场景。镇区使用独立设置和地图资源。

Unity首轮验收包括11项Editor测试（6项镇区、5项原Boss/异怪）全部通过、编译无错误，以及真实单人开房、普通移动、A区出怪、码头失败回执和军火铺成功购买14发手枪弹（300→270金币）。主控独立读取了测试任务和最终编辑器状态，确认正式场景、Play已停止、无编译错误；当前控制台仅有两条深度表面load/store提示。截图与验收记录保存在 `artifacts/drowned-bell-town/task5/`。Boss截图使用隔离的表现样本，未作为实际通关证据。

全量回归记录为 `artifacts/drowned-bell-town/full-verification.log`；主套件遇到旧模式委托四人UDP测试失败后，后续分组继续执行，记录在 `full-verification-resumed.log` 和对应status.tsv。已复现该委托失败并录下1130帧、4520条确认输入：一名玩家捕获数为0，团队已完成三项委托。相同输入在本次实现和基线c5444b3重放的捕获数、金币、位置和体力一致，且核对了基线256个源文件均与HEAD相同。证据见 `artifacts/drowned-bell-town/commission-regression-comparison.json`；这项既有自动游玩流程问题仍保留，不能宣称全量全绿。

未完成Unity实机A–F全程、四人通关和发布包验证。20～30分钟探索时长、4～6分钟关底时长和实机手感需要完整游玩调优，不能由规则测试和截图证明。静态路面采用0.5米保守采样，岸缘可出现约0.7米视觉内缩；木带使用精确旋转段。
