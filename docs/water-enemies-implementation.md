# 食人鱼与水怪实施说明

本轮按 `hook-island-game-design.md` 加入正式平台海域的食人鱼、水怪、水球、出钩打断和击退。沿用最新角色防御减伤，防御不抵挡水球击退。敌人规则、状态与结算位于 `samples/HookIsland.Simulation`，没有给通用帧同步核心引入玩法或 Unity 依赖。

## 配置与首版数值

Unity 配置入口是 `Assets/HookIsland/Data/EnemySettings.asset`，由 `FishingSettings.enemies` 引用。调整资产后使用现有 `Tools/Hook Island/Install Fishing Equipment` 安装入口重新生成正式地图配置；同房间客户端必须使用一致配置。配置内容参与地图、握手及存档兼容校验。

## 行为与衔接

- 食人鱼只选择在线、未倒地的落水玩家，优先最近者，同距按玩家槽位确定。可在平台下方游动，不攻击岸上玩家。冷却和位移的整数余量进入快照，包括最低合法速度的斜向移动。
- 食人鱼无落水目标时在出生点附近巡游。普通出钩可捕获，并已接入[多人合钓和反向抢钓](cooperative-fishing-implementation.md)：被钩住后按主钓方向牵引、暂停自主移动和攻击，仍挂线者均摊耐力；到岸后原子分配金币与鱼骨，再延迟刷新。取消、离线、倒地、耐力耗尽只移除对应线，最后一根线退出才释放活鱼；重复捕获／恢复不重复发奖励。
- 水怪平时潜水，前摇时浮出，发射或打断后在 0.5 秒内潜回。下一轮按确定性随机序列选择在线存活玩家，在其射程内不同的开放水面出现（至少相隔 1 m，优先在目标周围 3.5～6 m 随机选点）；随机候选无效时，遍历射程内的地块中心以覆盖缺口和大平台之外的水面。身体占地必须完整避开地板；找不到合法位置则推进并保存随机序列，潜水等待 1 秒重试。
- 水怪前摇开始锁定方向，发射后不追踪。目标倒地、离线或新增地块占据出水点会取消尚未发出的攻击。前摇有变色、脉冲圈和方向线；水球和受击有独立表现。
- 潜水水怪不阻挡钩索；前摇期间普通出钩命中取消本次发射并空钩返回。钩索在敌人攻击之前推进，因此最后一帧也能打断。冷却期间命中不会重复增加打断次数或无限延长冷却。
- 水球采用扫掠碰撞，先命中路径上的首个有效玩家后消失。同一次命中只结算一次。伤害使用 `ceil(D × 100 / (100 + 防御))`，防御不消耗。
- 命中后沿水球方向开始等级对应的击退，击退期间关闭主动移动。与已有队友钩救连接冲突时先断开连接；新水球命中重新开始一次击退。沿途扫掠有效地形和站位，离开平台即按现有规则进入水中，继而可能遭到食人鱼攻击。
- 落水持续伤害仍按游泳系统直接扣血，不经过防御；泳圈的免落水伤害不会免除敌人战斗伤害。
- 固定帧顺序为移动与外部击退、钩索、食人鱼、水怪及水球、落水环境伤害。每次攻击立即更新生命，因此同帧后续攻击不会继续选择已倒地者。

Unity `EnemyPresentation` 只读取确认状态，不使用 Collider 或本地物理进行战斗结算。模型为程序化网格，便于后续替换美术，不改变模拟规则。

## 状态、兼容和恢复

敌人阶段原始规则／状态版本为 13，输入版本保持 7，地图标识为 HIM9，敌人状态块为 ENM2。房间协议由同期房间重开任务升级为 14（不改变本轮敌人规则）。合钓接入后当前规则／状态与房间协议均为 15，地图为 HIMA，增加 COP1 钓线元数据，详见合钓实施说明。旧格式明确拒绝，不能用旧客户端混入新房间。

快照保存每条食人鱼的位置、重量、目标、攻击冷却和位移余量，食人鱼所有者／巡游目标／刷新倒计时，水怪等级／位置／出水随机序列／潜入进度／阶段／剩余时间／瞄准方向，水球序号／起点／方向／飞行进度，以及角色击退总距离／进度、钩中食人鱼 ID 和离线标志。中途恢复不会重置攻击、重新施加完整击退或生成第二只初始水怪。

反序列化校验配置、双向钩索归属、刷新与钩中状态互斥、等级、边界、方向、飞行帧数、水球序号与累计发射数、生成顺序及球龄。计数饱和后仍允许合法的 uint 序号回绕，拒绝回退序号、提前回绕、重复球和与飞行进度不符的球龄。禁用系统也不能携带随后会被丢弃的攻击计数。

## 本轮边界

食人鱼捕获与普通鱼收益已实现；水怪捕获、击杀、战利品与刷新仍未定义。水怪重量用于配置与显示，未擅自增加牵引玩法。水球目前穿过低矮平台设施，未来增加高墙时需显式设计阻挡规则。倒地复活与失败沿用已接入的复活系统；本轮验证战斗链路与多人状态一致性，不将其描述为完整游戏已完成。
