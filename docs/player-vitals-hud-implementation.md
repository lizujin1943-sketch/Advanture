# 角色状态 HUD 实现记录

2026-10-27。适用正式木平台场景 `HookPlatform.unity` 的装备模式。

## 显示与交互

- 所有可见角色头顶显示血条；自己的第三人称角色也显示。头顶锚点跟随头部骨骼，倒地、游泳和受击位移沿用表现层姿态。原底部生命／耐力面板移除，同时取消该区域的鼠标输入遮挡。
- 生命相关的血条、角色面板生命文字、扣血数字、倒地／死亡标志统一为血红色。屏幕目标色为 `#C4121C`，在线性色彩工程中先转换 UI tint，防止最终显示偏粉。玩家席位颜色仍表示玩家身份。
- 自己的耐力未满时显示在角色左侧，以加粗的土黄色短圆弧连续填充，总弧度约 104°，没有刻度、常驻数字或背景面板；满值及倒地隐藏。队友收鱼或主动游泳且未满耐力时显示自己的圆弧。恢复、落水、游泳圈及低饥饿保留必要小图标；详细数值只在角色面板或悬停提示中显示。
- 扣除耐力时，实际填充立即缩短；浅金色残影停留 0.18 秒后向实际值收拢。血条受击先以白色标出损失段约 0.1 秒，再由血红色填充在约 0.32 秒内平滑退到实际值。新增反馈及验证见 [HUD 精简与收获反馈](hud-refinement-implementation.md)。
- 取消第三人称屏幕中心的十字准星；仍沿现有镜头中心射线瞄准。俯视指向瞄准、鼠标转向、落点提示、出钩及命中计算保持既有规则。

## 状态来源和职责

- `PlayerVitalsOverlay` 只读取 `room.State` 确认快照，血量、当前耐力和装备上限来自同一快照。位置锚点跟随 `FishingPresentation` 显示的角色，不回写模拟状态。
- `HealthDamageFeedback` 比较连续确认快照的实际生命减少量；同帧重绘去重。120 毫秒内的短促伤害合并，最多保留每人 4 个数字，分列避免重叠，1.05 秒上浮淡出。一次显示可能合并两次渲染之间的多个模拟伤害，不是独立伤害日志。
- 初次接入、房间对象变化、局号变化、确认帧回退均建立新基线；菜单中继续观察但不积压飘字。生命装备卸下造成的上限裁切不当作伤害。治疗和复活增加血量不显示扣血。
- `StaminaArcPainter` 生成两张可重复使用的抗锯齿遮罩，用 UV 裁切绘制连续进度，不逐帧生成贴图。视图销毁时释放贴图。原 `ReelingStaminaOverlay` 横条移除，挣脱与合钓身份提示接入头顶区域。
- 未变更模拟规则、网络命令、协议或存档格式。没有向正式场景添加自动游玩组件。

## 验证与边界

- Unity 2022.3.62f1 编译通过。新增 5 项扣血反馈测试：重复 GUI、初始／重连／重新开局、治疗／换装、隐藏界面、多人独立及连续伤害合并。
- 针对 HUD、合钓提示、视角、连击布局、任务和商人输入边界的 54 项回归，首次 53 通过；既有 `FishingCameraViewTests.TwoUdpClientsWithDifferentPerspectivesMoveCastAndConfirmTheSameState` 首次移动断言失败（玩家 X 仍为 -1400），单独复跑通过。该测试只在开局前 6 帧输入移动，可能与启动时序有关，原因尚未定位。未修改该测试或网络实现，不能据此宣称整轮无失败。
- 最终颜色和飘字排布修改后，扣血反馈与 HUD 布局测试 16/16 通过。实际游戏通过临时普通移动输入走入水中，检查第三人称与俯视的头顶血条、扣血飘字、耐力弧和无准星，并确认最终渲染为血红色；截图位于 `artifacts/player-vitals-hud/`。临时输入仅在编辑器验收时显式设置，结束后清除。
- 这次只改 Unity 表现层，未运行完整 `./scripts/verify.sh` 或四客户端完整游玩。本次联机相关证据为确认状态来源、多人独立观察测试及既有双 UDP 视角测试复跑；未做四窗口视觉验收。

视觉参考：[任天堂《旷野之息》官方指南](https://media.nintendo.com/zelda/breath-of-the-wild/assets/ExplorersGuide.pdf)中的环形耐力读数方式。圆弧为本项目独立生成。
