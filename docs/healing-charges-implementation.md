# 个人次数回血

2026-11-04，替代原先的椰子、烤鱼和海鲜餐回血。已接入正式 `HookPlatform` 场景。

## 已确认规则

- 每人新局获得 3 次。每按一次 **V** 只尝试使用一次，长按不连续使用；**没有冷却时间、读条或进食动作**。
- 单次恢复当前生命上限的 40%，不超过满血。采用整数向下取整、至少 1 点；例如上限 125 恢复 50，上限 201 恢复 80。
- 实际恢复生命才扣 1 次，不消耗金币、物品、耐力或背包空间；满血、次数为零或状态不允许时不消耗。
- 仅成功付费复活补满 3 次，包含单人自动付费复活。付费失败、队友救起、读档、重连、换装都不补次数。
- 商店移除回血食物，整批补货也不再生成食物库存；旧购买／食用请求不能提供额外治疗。默认快捷位不再绑定食品。
- **C** 接替原来的视角切换；模式和持枪机位沿用现有规则。`1–4` 分类武器入口仍是设计，未在本次实现。

沿用原有状态限制：岸上存活、钩索已收回，且没有挥击、施救、拖拽、击退、举枪、射击收势或换弹。普通岸上移动允许使用。回血不能代替队友救起或付费复活；不恢复耐力、不授予无敌。

## 接入与状态边界

`HealingConfig` 保存次数和最大生命千分比，默认 `3 / 400`。Unity `FishingSettings.asset` 对应 `healingCharges=3`、`healingPercent=40`，不再存在回血冷却配置、计时或存档字段。正式 `PlatformMap.bytes` 已重新导出，生成 DLL 已同步。

`HealingSystem` 在纯 C# 模拟层统一检查条件并同时增加生命、减少次数；新局初始化和成功付费复活调用补满入口，免费救援不调用。`InventoryAction.Heal` 无物品目标，复用可靠请求编号及确认回执；同一个成功或失败编号不会重新执行。并发库存操作沿用一次一个待确认请求的输入规则，不缓存失败请求。

`Fisher.HealingCharges` 与生命和回执一同进入快照。非法次数、陈旧格式或配置不匹配的快照被拒绝，不覆盖当前状态。规则／输入／状态兼容版本为 **39／15／34**，房间协议 **31**；地图标记 `0x4E4D4948`，状态标记 `0x4E534948`。沿用项目现行策略，不迁移旧版存档，新版存档正常恢复。

Unity 只从确认态读取剩余次数。2026-11-04 按确认的设计改为血条左侧的纯白医疗储罐：固定外轮廓、按次数从下向上填充，左下角显示剩余数字；3/3 全满、2/3 与 1/3 对应部分填充，0 时只留外轮廓。填充与生命值无关，未成功的回血请求不会让它减少。主界面不再显示 `V 回血` 或常驻 `R 换弹`；换弹进行中仍显示剩余确认时间。实现和验证见 [角色状态 HUD](player-vitals-hud-implementation.md)。

输入仍使用 `Input.GetKeyDown(KeyCode.V)`，松开后再次按下才产生下一次请求。`Healed` 确认事件携带实际恢复量与剩余次数，驱动回血飘字和音效；预测、重发及存档恢复不补播反馈。旧食品模型与通用物品类型保留为历史资源，不再从正式商店供给或用于回血。
