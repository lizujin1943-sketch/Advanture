# 深渊凝视者：Blender 建模、绑定与动画设计

日期：2026-11-03。状态：设计稿，模型和动作尚未制作。

## 1. 目标与交付范围

以[原始概念草图](../../concepts/cthulhu-octopus-boss-v1.png)为外观主参考，制作尽可能还原设计、可编辑且可摆姿的巨型章鱼 BOSS。交付 Blender 原件、材质贴图、骨骼绑定及登场、待机、下砸、横扫、抓取抛掷、喷墨、断肢、狂暴、死亡动作。

## 2. 已确认的设计

| 内容 | 最终规则 |
| --- | --- |
| 位置与朝向 | 位于环形平台中央的海域；身体位置和整体朝向固定，头部只能小幅偏转。 |
| 出水形态 | 开战前从海中升起；战斗中整个头部始终露出水面；死亡时允许整体下沉。 |
| 身体外观 | 灰绿、略湿的软皮，粗糙的不对称礁壳、藤壶、吸盘及腕间薄膜；三只眼保留草图布局。 |
| 八条触手 | 前四条攻击，后四条主要支撑、摆动；八条均有独立血量，均可摧毁。 |
| 血量关系 | 本体和触手血量完全独立；本体归零即胜利，无须清空所有触手。 |
| 触手损毁 | 从根部断开，断肢落水下沉，留下暗色残端与少量黑墨；本场不再生。 |
| 攻击并发 | 同时最多 1～2 条攻击触手发招。 |
| 下砸 | 举高后向下砸，直接击碎从平台内圈指向外圈的长条区域；暂按一块地板宽、连续 2～4 块地板长制作。 |
| 横扫 | 触手横向扫击玩家；用户仅指定下砸直接击碎平台，制作初版不为横扫额外增加毁板效果。 |
| 抓取 | 缠住、举起、短暂停顿，越过平台抛向外海。被抓期间不能开枪；队友摧毁该触手可提前解救。 |
| 喷墨 | 放射状齿瓣张开，向正面扇形喷出带青绿荧光的浓黑墨汁；落地形成短时持续伤害和减速区域。 |
| 弱点 | 中央大眼承受更高伤害，但不能被单独摧毁。其余头部和触手仍可攻击。 |
| 狂暴 | 低血量时眼睛及皮肤裂隙发光增强，动作更猛烈；礁壳不脱落。 |
| 死亡 | 眼睛熄灭、头部下垂、剩余触手瘫软，最后整体沉海。 |
| 平台断路 | 玩家可以游泳绕行，也可以消耗材料修复平台。 |

设计的直接结果：后半圈相对安全；四条攻击触手全部损毁后，BOSS 只剩正面喷墨。后四条不因此获得攻击动作，头部不因此改为全周旋转，也不追加再生。这个结果保留在方案中，供后续游戏平衡评估。

## 3. 外观还原与补齐参考

首先对齐主图中的大轮廓：高而宽的囊状头冠、偏向一侧的大块礁壳、中央竖眼与两侧小眼、眼下暗色放射状口器、粗壮而逐渐变细的触手。保留眼窝、口器和触手之间的空间，不让表面小颗粒掩盖轮廓。

需要补齐以下参考，但不同视图必须描述同一个结构：

1. 全身正面、背面、左右侧面、顶面、底面；同一尺寸与姿态，去掉海水遮挡。
2. 八条触手的根部连接图，明确前四条与后四条的身份及腕间薄膜范围。
3. 头部正侧面、张嘴与闭嘴；中央眼、侧眼、齿瓣及眼睑的局部结构。
4. 触手根部、中段、末端，吸盘排列和断口封闭结构。
5. 无强烈光影的颜色与材质板，分开皮肤、礁壳、吸盘、口腔、眼睛和裂隙。

背面、腹面和内部口腔属于原图未展示的补充设计：沿用既有材质与形体语言，不增加新眼睛、额外嘴巴、翅膀、腿或攻击器官。左右按生物自身方向标记，不能在不同视图中互换不对称礁壳。

生成的设定图须校对比例、眼位和八条根部的对应关系。基础模型建立后，从同一个模型输出各方向参考，持续对照主草图修正。原画展示姿态与方便绑定的舒展姿态分开保存。

## 4. 尺寸与战场对照：制作初值

| 项目 | 初值及用途 |
| --- | --- |
| 海面到头顶 | 10 米。 |
| 头部最宽处 | 约 8 米；侧面厚度根据正侧面统一调整。 |
| 触手自然姿态展开 | 约 26 米，保留草图中弯曲、抬起与入水的变化。 |
| 触手根部直径 | 1.2～1.5 米，向末端平滑收细。 |
| 环形平台 | 对照场景先采用内半径 12 米、宽 8 米，外半径 20 米；地板沿用约 2 米尺寸。 |
| 下砸长条 | 约 2 米宽、4～8 米长，沿半径方向跨过平台，实际破坏仅覆盖存在的地板。 |
| 攻击触手最大覆盖 | 骨链舒展后需能覆盖距 BOSS 中心约 20～22 米的外圈；自然姿态不能当作最大伸展长度。 |

当前手枪射程配置为 12 米，因此主要攻击站位安排在平台内圈，外圈供躲避、移动和修复。用正式角色与相机视角检查这些初值，再调整平台内径、触手弧长和摄像机观察位置，不能只看俯视截图确认体型。

玩家参照优先使用仓库 `source-assets/characters/fisher/Fisher.blend` 中的实际角色比例；先前聊天中的 1.8 米只是比较示例。抓握空隙和抛掷高度必须按实际角色检查。

身体位置固定不等于表面僵硬。待机可有小幅呼吸，头部初步限制左右偏转约 15 度；具体幅度由眼睑、礁壳与根部是否穿插决定。任何待机或攻击片段都不能悄悄累计身体平移、转身或把整个头部沉入水下。

## 5. 模型拆分与材质

| 部件 | 制作方式与目的 |
| --- | --- |
| 主体、头冠与腹面 | 完整体积，补齐背面和水下部分；不能只做面向镜头的一张壳。 |
| 礁壳与藤壶 | 作为附着结构保留大块轮廓，随所在部位运动；狂暴不脱落。 |
| 眼睛、眼睑、口器 | 分别可控制开合和发光，眼窝有深度，嘴里有真正的暗腔和齿瓣。 |
| 八条触手 | 每条单独可隐藏、拆卸；身体和相邻触手不能共享导致撕裂的受控顶点。 |
| 吸盘与薄膜 | 近处吸盘保留真实凸起及凹口；沿触手变形，避免弯曲时漂浮。薄膜不能跨接两条需要独立脱离的触手。 |
| 断口 | 身体残端与断肢近端都须封闭。完整时由连接处遮住，摧毁后不能露出空洞或看到模型背面。 |

皮肤与礁壳使用不同的粗糙程度；青绿发光集中在眼睛及受控裂隙。细小皱纹与碎裂纹可以用贴图表达，主要礁壳、吸盘和口器轮廓必须有实际形体。材质整理成可随模型交付的颜色、粗糙度、法线与发光信息，不把 Blender 预览灯光烘成固定的皮肤阴影。

还原大轮廓和近处细节优先。具体网格数量、贴图尺寸由制作阶段根据镜头距离和导出验证安排，记录实际结果，不用任意的低面数限制提前删去设计特征。

## 6. 骨骼与控制分工

采用一个总控制、独立头部控制和八条独立触手骨链。每条触手的骨骼像一串沿着触手排列的关节；控制点用于方便摆姿，导出动作时转换成可播放的普通骨骼关键帧。

| 控制区域 | 职责 |
| --- | --- |
| 总控制 | 定位、整体出场及死亡下沉；正常战斗锁定位置和朝向。 |
| 躯干与头部 | 呼吸、小幅转头、受击及死亡垂落。 |
| 三只眼及眼睑 | 注视与眨眼；主眼不做单独损毁。 |
| 口器 | 齿瓣开合、喷吐蓄力；设定明确的墨汁喷出位置。 |
| A01～A04 | 前四条攻击触手，分别完成下砸、横扫、卷握、举起和外抛。 |
| S01～S04 | 后四条支撑触手，完成待机、受击、断肢和死亡；不制作会被自动启用的攻击逻辑。 |
| 每条触手的根部 | 为断肢提供稳定分离位置，保留本体封口与断肢封口。 |
| 攻击触手的抓握点 | 标出玩家躯干附着的位置与朝向，供抓取演示和后续游戏接入。 |

前四条骨链初步考虑每条约 14～18 个变形关节，后四条约 8～12 个；以卷握、横扫和根部弯曲是否顺畅为调整依据。控制用的辅助骨骼与实际改变网格的骨骼区分命名，导出时不依赖编辑器里的控制形状。

每条触手的动作只控制自己的区域。A01 下砸时，不得把 A02 的抓握或其他触手的待机重置。触手被移除后，其动作不再驱动身体残端。已脱离的部分不继续跟着本体的转头或死亡下沉移动。

抓取姿态采用围绕躯干的卷握，避免从头部或四肢穿过；玩家根部跟随抓握点，头、手和枪的摆放按现有角色验证。禁止开枪是后续游戏规则，不依靠把枪塞进模型里表达。未被解救时，动作必须有限时地推进到抛出，单人游玩也不会永久被束缚。

## 7. 动作清单与组合

| 动作 | 可观察的动作过程与关键位置 |
| --- | --- |
| 登场 | 整体从海中升起，触手展开，睁眼；结束姿态接入原画中的出水轮廓。 |
| 待机 | 呼吸、头部小幅偏转、眨眼、触手缓慢起伏；循环衔接无突然跳动。 |
| 下砸：A01～A04 各自一套 | 抬起蓄力、沿径向长条砸落、触地停顿、收回；标出实际落地时刻和覆盖线。 |
| 横扫：A01～A04 各自一套 | 明显后摆、低位横扫、收回；控制高度，保持玩家能读出攻击方向。 |
| 抓取外抛：A01～A04 各自一套 | 靠近、卷握、举起、停顿、甩向平台外侧、松开、收回；标出抓住和释放时刻。 |
| 喷墨 | 头部仅小幅瞄准正面区域，口器蓄力张开、喷出、闭合；不做背向喷射。 |
| 断肢：八条分别可演示 | 根部脱离，身体露出残端，断肢保持脱离瞬间的形状后落水下沉。 |
| 狂暴 | 眼睛与裂隙增强发光，呼吸和攻势更猛烈；不恢复已断触手，不新增攻击部位。 |
| 死亡 | 中止攻击、解除玩家抓取、熄眼、垂头、剩余触手软落、整体沉海；已断部分不重新出现。 |

动作至少包含“预备、触发、收回”三个阶段。具体时长由制作者给出可调整初值，优先保证巨大生物的重量感和第一人称玩家的观察时间。狂暴不能通过完全删除预备动作来表达。

制作单条触手动作，也制作组合演示：两条攻击触手同时活动、喷墨叠加触手动作、抓取中触手被摧毁、部分触手缺失时死亡。演示中的玩家参照、海面和地板只用于检查动作，不据此宣称游戏规则已经实现。

## 8. 文件与后续游戏接入

计划产出采用仓库现有源资源目录约定：

- `source-assets/creatures/abyssal-watcher/AbyssalWatcher.blend`：可编辑模型、材质、骨骼、命名动作及验证场景。
- `source-assets/creatures/abyssal-watcher/textures/`：模型使用的贴图。
- `source-assets/creatures/abyssal-watcher/exports/`：供 Unity 使用的骨骼模型与烘焙动作 FBX，附带部件、动作、抓握点、喷墨点和断口名称清单。
- `docs/concepts/abyssal-watcher/`：补齐的参考图与设计说明。
- `artifacts/abyssal-watcher/`：渲染图、动作预览和验证记录，不提交 Git。
- 如制作过程使用脚本，放入 `scripts/blender/`，不在旧工作目录或系统临时目录维护唯一源文件。

这些路径是计划，不表示文件已经存在。`.blend` 与导出文件应能重新打开；导出物重新导入空场景后检查比例、骨骼、材质和动作，不能只验证文件名存在。

骨骼运动通过烘焙关键帧交付。发光强度变化、部件显示切换、喷墨特效和玩家附着/释放另外记录发生时刻及参数，不假设单个 FBX 会自动表达全部游戏行为；Blender 演示与后续 Unity 接入使用同一份事件说明。

后续游戏接入需要：本体与八条触手的稳定编号、抓取者与被抓者关系、动作阶段、断肢状态、平台破坏和危险区状态。上述规则由纯 C# 游戏模拟决定，Unity/Blender 骨骼负责显示；不把 Unity 浮点骨骼位置直接作为各端独立结算伤害的依据，帧同步框架不增加 BOSS 专用逻辑。

当前枪械命中仍以二维平面射线检测为主。射击高处主眼、分别命中触手、抓起及抛掷等需要后续明确的确定性判定与状态扩展，不能仅给模型挂碰撞体就宣称已接入。该接入工作不混入本轮资产完成标准。

## 9. 制作顺序与完成证据

1. **统一参考与比例。** 补全结构参考；搭建头部、八条触手、环形平台和实际玩家比例，核对出水轮廓及攻击覆盖。
2. **完成形体和材质。** 完成眼口、礁壳、吸盘、薄膜、腹面与封闭断口；保存与主图角度一致的对照渲染。
3. **绑定与动作。** 先验证卷握与最大伸展，再完成各动作及组合；测试每条独立断肢和抓取释放。
4. **导出与交付。** 打开源文件和导出物复核，保存实际预览及问题记录。

验收必须有下列可查看证据：

| 要求 | 应提供的证据 |
| --- | --- |
| 还原外观 | 主图角度的并列对照，以及正、侧、背、顶、底渲染；检查头冠、眼口、礁壳位置和触手轮廓。 |
| 八条结构完整 | 清楚的顶视编号及逐条隐藏检查；没有多余触手，背面和腹面不是空壳。 |
| 绑定实际可用 | 下砸、最大伸展、横扫、卷握和头部偏转的实际播放；吸盘不漂浮、薄膜不撕裂、弯曲处不过度塌陷。 |
| 断肢可靠 | 八条逐一演示分离，检查双侧封口、相邻触手不被带动、断肢脱离后不跟随本体。 |
| 完整动作 | 清单中的各动作与双触手组合均可播放；四条攻击触手都具备完整动作，支撑触手无攻击行为。 |
| 抓取规则对应 | 用现有角色检查卷握、举起、被队友解救时提前释放、越过平台外抛；被抓时禁止开枪的正式规则留给游戏接入验证。 |
| 残缺状态正确 | 前四条全部消失仍能喷墨；任意支撑触手缺失时不复活；死亡动作不会恢复断肢。 |
| 尺寸与环形场地 | 第一人称、常用游戏视角及俯视对照，看到长条下砸覆盖平台和抛掷落点位于外海。 |
| 文件可交付 | 源文件与导出物重新打开后的检查记录，无缺失贴图，部件、动作和标记命名对应。 |

当前没有任何模型、绑定、动画或导出验证通过的声明。完成后逐项填写实际证据；数值检查不能代替视觉还原和动画播放检查。
