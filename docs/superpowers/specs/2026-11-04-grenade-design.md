# 第一个投掷物：手榴弹

2026-11-04。状态：玩法与接入设计，尚未实现或试玩。正式仓库为 `/Users/lizujin/Documents/project/git_project/Advanture`。

## 已确认的体验

- 每位玩家默认有 1 颗手榴弹，各自独立消耗。
- 操作参考拿出、瞄准、投出的流程；鼠标选择大致落点，手雷落在附近。
- 投掷瞄准时只拉远当前镜头，保留当前观察方向，不强制切到斜俯视。
- 按住左键瞄准时释放光标，直接指向地面。
- 爆炸伤害自己和队友。
- 落地后短暂延时爆炸；按住瞄准期间不开始倒计时。

以下具体按键流程、数值、补充规则及实现安排为首版建议；不把它们写成已经过试玩的结论。

## 一次完整投掷

| 阶段 | 玩家操作 | 看到的反馈 |
| --- | --- | --- |
| 拿出 | 按 `4`，切到个人手雷 | 手持手雷，右下显示纯白文字 `手榴弹 ×1`；保留当前观察方向 |
| 进入瞄准 | 按住左键 | 镜头平滑后拉，释放鼠标；显示落点圈、细抛物线和爆炸范围 |
| 调整落点 | 移动光标，仍可 WASD 移动 | 地面落点随鼠标更新；超距或被阻挡时变红 |
| 投出 | 在有效区域松开左键 | 锁定这一刻的目标，播放投掷动作；确认投出时才扣除手雷 |
| 飞行与落地 | 无需继续按键 | 手雷沿抛物线飞到目标附近，落地后亮起短暂警示 |
| 爆炸与回枪 | 正常移动、继续作战 | 落地 0.8 秒后爆炸；投出动作结束便切回上一把武器并恢复镜头，不等爆炸 |

按 `4` 只拿出手雷。镜头后拉与光标选点从按住左键时开始，避免仅检查手雷数量也改变构图。切到手雷时应保留进入前的镜头类型与朝向，防止现有“收起枪械后恢复旧视角”的代码提前改变观察方向。

瞄准时镜头朝向固定，鼠标只选落点；玩家仍按进入瞄准时的镜头水平方向移动，镜头继续跟随人物。如果想换观察方向，先取消瞄准、转向，再按住左键选点。首版使用一种固定力度的高抛，按住更久不会增加距离。

## 取消、中断与忙碌

- 右键取消瞄准，保留手雷；松开左键后才可开始下一次瞄准，不能把取消后的松手当成投掷。
- 按 `1/2/3` 取消并请求切换到对应武器。空槽切换失败时仍取消瞄准、保留手雷。
- 在无效落点松手时取消本次投掷、保留手雷，并短暂提示原因；不会等鼠标以后移到有效位置再补扔。
- 打开菜单、背包或商店、失焦、倒地、死亡、离房时清除尚未提交的瞄准。恢复焦点后要求重新按键，不自动投出。
- 正在瞄准时暂不响应 `C` 或滚轮缩放，避免改变选点坐标；退出后恢复原有操作。
- 松手并提交请求后不能用本地右键撤回；此时由逻辑中的出手动作处理成功或中断，避免本机取消、其他端却已经投出的分歧。
- 已经成功生成的手雷独立存在。投掷者倒地、死亡或断线，都不取消它的飞行和爆炸。
- 瞄准中允许移动，不允许同时开火、近战、建造、治疗或救援。进入手雷的切换沿用现有武器忙碌限制；成功切换可以取消换弹。

## 镜头与地面选点

镜头只在本机变化，不进入联机输入或世界存档。

| 项目 | 首版建议 |
| --- | --- |
| 透视镜头后拉 | 沿当前视线反方向额外后拉 2.0 米 |
| 后拉 / 恢复时长 | 0.2 / 0.2 秒 |
| 方向和视野角 | 保留原 yaw、pitch 和 FOV，不自动俯视、不放大视野角 |
| 原俯视为正交投影时 | 沿原视线后退，并把取景范围临时扩大至进入前的 1.2 倍；退出恢复 |
| 遇到场景遮挡 | 缩短后拉距离，使镜头留在可见区域；不强行穿墙 |

第一人称后拉后可能看到自己的完整身体，显示层应恢复该身体，并暂时隐藏贴在镜头前的枪械与双手。恢复第一人称时再恢复原有可见性。此过程不改变角色的命中体积。狙击开镜在拿出手雷时关闭；回枪后需要重新按右键开镜。

从拉远后的相机向光标位置发出选点射线，只接受共享地图数据支持的地面或水面，不将敌人身体当成落点。视线朝向天空、没有可选表面、超出投掷距离或抛物线路径被障碍挡住时，显示红色无效标记。

显示层用同一套投掷规则预览轨迹与有效范围；逻辑执行时再用执行帧的角色位置校验距离和障碍。网络延迟期间玩家移动可能让请求失效，此时返回失败、保留手雷。

投出后目标固定，不再随光标移动。镜头恢复的是原模式、朝向和距离，并跟随角色当前的位置；不能恢复成进入瞄准时的旧世界坐标。

## 落点、飞行与起爆

目标是“能投到选定区域”，首版采用可控抛物线，并用落点小圈表达误差。

| 项目 | 首版建议值 | 用途 |
| --- | --- | --- |
| 最远投掷距离 | 18 米 | 能越过近处敌群，也需要靠近战场 |
| 最近投掷距离 | 1.5 米 | 避免手雷生成在自己脚底 |
| 落点误差半径 | 0.35 米 | 手雷落在小圈内，保持选点的意义 |
| 飞行时间 | 0.6～1.0 秒 | 随距离增加，按逻辑帧取整 |
| 抛物线额外弧高 | 2～4 米 | 随距离增加，允许跨越较低障碍 |
| 落地后引信 | 0.8 秒，即 24 个逻辑帧 | 当前模拟每秒 30 帧，给出短暂躲避机会 |
| 爆炸半径 | 4.5 米 | 中等规模群体伤害 |
| 满伤范围 | 中心 1.5 米内 | 直接命中附近目标更有价值 |
| 中心 / 边缘基础伤害 | 120 / 20 | 中间按距离线性衰减，半径外为 0 |
| 自伤 / 友伤倍率 | 均为 100% | 与敌人使用同一基础伤害，再计算各自防御 |
| 投出动作 | 约 0.3 秒 | 真正出手在其中一个固定逻辑帧发生 |

这些数值均放入手雷配置，后续试玩调整不改投掷流程。爆炸属于战斗伤害，复用护甲减伤与倒地处理；以 100 点生命、无护甲为例，站在满伤圈内会被炸倒。

落点误差由世界种子、投掷者和成功投掷序号确定，每次重放得到同一个偏移。预览显示误差小圈，不提前暴露这次具体偏移。逻辑在生成前校验包含误差的候选终点及路径；偏移造成碰撞时退回中心路径，中心也无效则整次失败、不扣数量。

首版手雷落地即停稳，不再远距离弹跳或滚出落点圈。轨迹途中使用共享地图的整数障碍检测，防止隔墙穿过；障碍要有高度信息，足够高的抛物线可以越过低障碍。玩家和敌人不会阻挡飞行，也不会被手雷本体撞伤。动态障碍在飞行中阻断路径时，手雷停止水平运动并向下落，真正接触地面、障碍顶面或水面后才开始计时。

水面也可作为落点。手雷入水后停留在水面下 0.3 米，从入水帧开始计时，爆炸表现改成水花。首版水中仍使用同一伤害规则；不模拟浮力、漂流或深水沉底。

延时从逻辑判定的落地帧起算，不能依靠动画结束、音效或 Unity 碰撞回调。生成帧只生成飞行对象，从下一帧开始推进；若在帧 L 落地，则在 L+24 帧爆炸一次。

## 爆炸结算

- 以实际爆炸点为中心，按二维平面距离筛选目标；高度用于飞行和障碍检测，伤害范围沿用当前平面玩法，不宣称真实三维冲击波。
- 对伤害接收点检查实体障碍遮挡，厚墙完整阻挡；不因画面的粒子穿墙就扣到另一侧目标。
- 自己、队友和敌人均可受伤；同一个目标只结算一次。沿用现有生命、护甲、倒地、死亡和击杀归属。
- Boss 的本体与独立触手各作为一个伤害部位，每部位只结算一次；多个部位命中不重复累计到本体，爆炸不触发眼部射击暴击。
- 首版只伤害战斗实体，平台、建筑、商人、宝箱和地面物品保持原规则。爆炸有镜头震动与音画反馈，暂不施加额外击飞。
- 已倒地或死亡角色沿用现有状态规则，不借手雷新增处决或复活规则。同一逻辑帧多颗爆炸按稳定的投掷物 ID 顺序处理。

## 数量、库存与 HUD

首版给每位新角色 1 颗真实的手雷物品，直接放进新的投掷物装备槽。手雷在背包时占 1×1 格，投掷物槽首版容纳 1 颗；不恢复屏幕物品快捷栏。首版不新增商店补货，但数据仍进入正式库存，保留以后购买、拾取和转交的接入方式。

投出时先记录上一把有效武器的 ID。出手成功后从本人库存消耗这 1 颗，并生成唯一的飞行手雷；两件事要么同时成功，要么都不发生。手雷用完后按上一把武器回切；该武器已失效时沿用现有手枪、主武器、近战回退规则。

成功投出前取消不消耗。新局或新角色获得初始手雷；读档、掉线重连、倒地救起和付费复活保留当前数量，不重复赠送。已经投出的手雷不再占投掷物槽，数量为 0 时按 `4` 仅短暂提示“没有手榴弹”。

右下角只在持有手雷时，用纯白文字 `手榴弹 ×1` 显示当前装备数量，替换枪械弹数；回枪后恢复弹药读数。沿用当前简洁 HUD，不添加右侧武器图标、背板或物品栏，继续隐藏任务及常驻按键教学。

世界模型建议使用橄榄绿罐体、深灰金属压柄与清楚的拉环轮廓，保持现代装备观感。拿出、准备与投出的动作在本地近景和其他玩家的世界角色上都可辨认；落地警示闪光与短促提示音明确表达即将起爆。

瞄准地面提示包含：白色小落点圈、较淡的 4.5 米爆炸圈和细轨迹线。无效时改红并给出“超出距离／路径被挡住”等短提示。出手后，所有客户端都能看到手雷；进入爆炸范围的玩家看到明显的落地警示，避免只有投掷者知道危险。

## 代码接入边界

只扩展游戏模块和 Unity 适配层，通用帧同步框架不包含“手雷”概念。

| 部分 | 承担的职责 |
| --- | --- |
| `HookIsland.Simulation` 的投掷物目录与配置 | 保存距离、弧高、延时、伤害和物品定义 |
| 库存与 `WeaponLoadout` | 接入第 4 类、所有权、上一把武器、物品消耗和失败回执 |
| 新增投掷命令 | 携带请求编号、手雷物品 ID 与目标 X/Z 毫米坐标；不上传“我炸到了谁” |
| 新增投掷模拟 | 在固定帧中处理出手、飞行、实际落地、引信和爆炸；使用整数计算 |
| 世界状态与序列化 | 保存个人投掷动作、已处理请求及所有仍在场内的手雷，供回滚和存读档 |
| Unity 输入 | 管理拿出、按住、松开、取消及失焦清理；把意图交给既有输入通道 |
| Unity 镜头与落点预览 | 临时后拉、释放光标、轨迹线、范围圈以及正确恢复视角 |
| Unity 手雷与爆炸表现 | 根据模拟状态显示飞行和落地；确认事件播放一次音效、粒子和震动 |

在现有 `HookInput` 中增加独立投掷命令，接入所有复制、组合、编解码及校验路径，不能只改鼠标适配器。第 4 类也要一起检查枚举上限、忙碌限制、切换、库存校验、存档和表现，不能只在 `WeaponLoadout.Slots` 后面追加一个值。

请求在首次提交时冻结目标，同一个请求号重传仍使用同一目标。失败也要保留回执；回滚、丢包或读档后不能补扣或补生成。请求号及回执随状态保存，重新开局才进入新一轮编号空间。确认处理后，客户端清除相应待提交命令。

模拟保存手雷唯一 ID、投掷者、来源物品、出手与落地帧、起点与终点、飞行进度、当前位置、阻断后下落所需的垂直运动量和起爆阶段。玩家保存待出手动作及回切武器 ID。进入出手动作后禁止重新瞄准；在真正出手帧再次校验物品、距离和路径，若此前倒地、被打断或校验失败则取消、不消耗，并记录最终回执。既有库存请求忙碌检查需覆盖这些阶段。

各端执行同一份逻辑，Unity 的 Rigidbody 和碰撞回调只可做装饰，不决定真正落点或伤害。共享障碍信息从玩法地图读取，预览也调用同一规则；动态平台改变时按当前逻辑帧重新检测。

世界快照必须保存空中和落地等待的手雷。读档后从原进度继续，已经爆炸并移除的手雷不能复活。输入、状态、库存和玩法规则版本及地图配置哈希一起更新，沿用现有不兼容旧档时明确拒绝、保留原文件的策略。

## 建议实现顺序与验收

1. 先在纯 C# 接通物品、第 4 类、投掷请求和可保存的手雷状态；验证初始 1 颗、取消保留、失败不扣、成功只扣一次、切回武器。
2. 完成整数抛物线、障碍、落地后 24 帧起爆、范围衰减、遮挡、自伤友伤及既有敌人与 Boss 部位伤害。检查空中和落地中的存档恢复，以及输入重放一致性。
3. Unity 接入当前镜头后拉、自由光标、落点预览、手持模型、投掷动作和 HUD；检查第一／第三人称与现有俯视模式、取消、失焦和回枪。
4. 四个真实 UDP 客户端验证同时投掷、重传去重、投掷者断线、空中保存恢复及所有端检查点一致；再进行实际键鼠手感和危险范围可读性验收。

首版验收不能只看到爆炸效果：需要看到所有端的手雷数量、落地帧、起爆帧、伤害及最终状态一致。真正开始实现前，再把本设计拆成具体改动和验证计划；本文不把设计完成描述为功能已交付。
