# Yard07 双客户端帧同步接入

日期：2026-10-16。用户要求把现有第一人称试玩接入帧同步，两端能互相看到移动和转向，框架保持独立。

## 边界与实现选择

- 沿用 Unity 2022.3.62f1、C#、现有 ServerSession / ClientSession / ReliableUdp。所有产出留在正式仓库。
- `framework/` 继续只处理输入字节、帧、快照和传输；不出现角色、地图、UnityEngine 或 Steam。
- `samples/TacticalGame.Simulation` 是纯 C# 游戏规则：毫米整数位置、世界平面的量化移动方向、百分之一度朝向、静态矩形障碍。输入采样可以使用 Unity 浮点，采样结果编码成整数后才参与模拟。
- `samples/TacticalGame.Network` 是纯 C# 示例宿主：双人房间握手、Socket 生命周期、固定帧输入调度、现有会话的调用。它依赖游戏模块，不能移入通用框架。
- `adapters/Unity` 是本地 Unity 包与框架程序集导入入口；游戏程序集进入示例的 Plugins。构建脚本从同一源码生成 DLL，不手工复制修改核心源码。
- Unity 只采集键鼠和展示状态。联机不调用 CharacterController.Move；角色碰撞由所有模拟实例运行同一整数规则。原本地试玩场景保留，新增联机场景作为联机构建入口。

## 玩家体验

创建双人房间或输入 IP/端口加入。房主程序同时运行服务器与自己的客户端；本地客户端也经过 UDP 输入链路。两人准备完成后才启动时钟；每秒 30 逻辑帧，输入提前 3 帧。角色用有朝向标记的双色简模表示；本地第一人称相机隐藏自己的模型。

WASD、Shift、鼠标、R、Esc 沿用已有含义。失焦时发送中性输入而网络继续运行。鼠标朝向可在表现层立即响应；模拟使用量化后冻结的绝对朝向。远端显示已确认状态以避免中性预测造成停走抖动，本地位置显示预测状态。帧确认摘要一致才称为同步通过。

本次是本机/可信局域网直连；不实现公网穿透、Steam、中途加入、自动换房主或游戏存档界面。断线与退出必须有明确状态并释放 Socket；可以返回菜单重建房间。Windows 跨系统验证继续按用户之前决定暂缓。

## 确定性规则

输入包含世界 X/Z 方向（-1000..1000，向量长度不超过 1000）、可选绝对 yaw/pitch、加速和重置标记；没有操作也提交明确的中性输入。没有朝向标记时保留旧朝向，避免缺失输入把玩家转回零度。

位置用毫米整数，正常速度 4500 毫米/秒，加速 7000 毫米/秒。除法余数保存进状态，避免帧率除不尽丢失距离。玩家半宽 350 毫米；碰撞按固定 X 后 Z 顺序做扫掠与截断，避免穿薄墙并允许滑墙，转角相对原胶囊略保守。第一版没有跳跃、坡面和玩家互撞。

地图障碍与近距离、相互可见的两个出生点由编辑器从地图导出为初始化字节。所有客户端收到同一初态；地图字节与本机导出资源不匹配时拒绝开局，避免画面与碰撞错位。状态编码包含所有位置、朝向与运动余数，必须支持检查点恢复和输入重放。

## 验收

1. 核心原有本地冻结回归先复现再修复；核心完整验收恢复通过。
2. 游戏模拟自动测试覆盖编码拒绝非法输入、速度/斜向、转向/中性保留、碰撞、重置、保存恢复重放。
3. 无 Unity 的真实 UDP 房主加两个客户端验证双方移动和转向、全端同一确认帧哈希；准备期间不推进；拒绝第三人；断线/重建和资源清理。
4. Unity 导入与场景测试验证联机场景、地图导出、角色表示和本地视角绑定。构建两个独立进程执行有不同输入的联机验证，保存最终状态/哈希与画面证据；真实窗口验证创建/加入入口和可见远端。
5. 说明文档解释如何运行两个客户端、各层职责和已验证范围。不给未测的 Windows/公网/跨架构行为背书。
