# 外围补给船与独立商店设计

## 意图与范围

让“捕鱼／钓浮木 → 扩建 → 到新商人处换更好的装备”成为正式平台可玩的选择。已有五档商品概率不变；新增实际到达路线、各商人独立库存及换货时间，并让多人购买和恢复存档保持同一份货架。

本阶段延续总目标“实现需求文档中已经描述但尚未实现的玩法功能”。既有文档已经确定商人隐藏等级不升级、首次可交互即有货、每家独立十分钟换货、个人钱包和共享有限库存。外围固定船的位置、尺寸和引导方式是实现者初值；异步布局偏好题尚未收到答复，不把未回复记为用户批准。

不实现商船航行、停靠事件、原小岛连接、通用 NPC 对话、额外任务、价格变动、自动寻路或 Boss 上岸。到齐五家商店不成为终局门槛；当前局长不要求集齐全部最高档装备。

## 可试玩空间

平台中心仍是现有商人（ID 0、隐藏等级由原 MerchantLevel 配置，正式为 M1，交互中心 0／1 m）。四条独立可选支路从初始 3×3 平台向外延伸，没有免费桥，也不额外赠送材料。

| 商人 ID | 面向玩家的地标 | 配置隐藏等级 | 船中心（米 x／z） | 格子 x／z | 最少新增直路格数／材料 |
| --- | --- | --- | --- | --- | --- |
| 1 | 东侧补给船 | M2 | 10／0 | 5／0 | 3 格／12 |
| 2 | 北侧补给船 | M3 | 0／14 | 0／7 | 5 格／20 |
| 3 | 西侧补给船 | M4 | -18／0 | -9／0 | 7 格／28 |
| 4 | 南侧补给船 | M5 | 0／-22 | 0／-11 | 9 格／36 |

材料按现有每格 4 木头或 4 鱼骨计算，允许混铺；未包含自选加宽和回环。交互距离保持 3 m，必须整个人站在合法平台上。船是水中的补给点，不能站上船购物，也不能在船体格建造。玩家可从任意方向铺地接近。船占一个 2 m 格的保留水域，实际船体略小于该格；角色游泳、击退和拖拽不能穿过船体。水球与鱼钩仍沿既有水域规则飞行，船不是可钩目标。

目标行为是让玩家选择先用少量材料接近东船，或者投入更长支路寻找高档装备。每个分支的成本与鱼种分布由实际试玩检验，不以格数证明节奏已平衡。初值不强制先买上一档，也不因完成委托自动解锁商人。

船位置和等级进入确定性配置。额外商人最多四个，ID 固定连续 1～4，不能重叠、占初始平台或超出建造范围。地图把船体格纳入已有保留格约束，使建造、鱼群／水怪／终局选址都读取同一禁建区域；角色移动单独读取实际船体占地。重复编码和恢复不能重复添加保留格或改变地图摘要。

## 交互与可读性

外围船使用简单船体、货摊、旗帜及方向名称；不显示 M1～M5 或概率。屏幕内显示地标名，屏幕外显示与相机相对的方向和距离，避开左上任务、右上钱包、下方生命耐力及操作按钮。颜色仅辅助区分，同时保留文字和方向信息。船被发现和真正可购物分开表达，水中接近不出现“可购物”提示。

E 继续优先开附近已抵岸宝箱，再开最近可交互商人；等距时取较小 ID。打开后绑定该商人 ID，标题显示名称，货架和倒计时读取该商人的确认态。走远、落水、被拖拽、倒地、胜利或离开房间关闭店铺。换到另一商人或原商人换货时，清除旧商品选中状态；不能拿上一家的格子索引购买下一家的货。

购物保护沿用原规则：岸上打开店铺免疫友方拖拽，其他危险仍按原玩法处理；水中不允许打开商店。

## 库存、交易与时钟

- 每家保存 ID、是否激活、激活帧、批次、下次换货帧、每件商品及售出状态。
- 正式初始商人在开局已经可交互，激活帧为 0，保留原有首批和随机结果。外围商人第一次有可行动玩家站在其交互范围内时激活，立即生成第 1 批并启动自己的 600 秒计时。只游过、离线、倒地或被拖拽不激活。
- 激活后离开／重新打开／买空均不重置计时，也不升档。每帧先激活／处理到期换货，再处理购买；旧批次请求明确失败。未激活商人没有商品、批次和换货时间。
- 生成结果仅取地图种子、商人 ID、隐藏等级和批次；ID 0 保留现有算法结果，其余 ID 使用独立确定性随机序列。仍按已有货档概率、保底、陈列尺寸和衣装混排规则生成，不顺手改商品经济。
- 购买请求携带商人 ID、批次、商品索引及玩家请求号。检查指定商人存在、已激活、玩家在其岸上交互范围，以及原有余额、背包、换装和忙碌条件。成功才一起扣个人金币、交付物品、置该商品售出。其他商人不受影响。
- 同帧抢同一件商品按现有稳定席位顺序结算，只能成功一次；两人在不同商人购买同格同批商品可分别成功。
- 成功和失败回执都保存，重试同请求不再次结算；换货、换商人、恢复或重连不能把已失败请求隐式重放。旧 RodAction 兼容入口明确只针对 ID 0，正式界面使用带商人 ID 的库存命令。
- 现有 InventorySystem 继续唯一拥有装备和物品；商店系统只拥有货架与时钟。快照恢复校验各商人集合、激活时间、批次时钟、确定性商品内容和规范未激活状态。当前售出状态原样保留，恢复不重新抽货。
- 原房间重开恢复初始 M1 首批，其余商人未激活；上一局购买输入由既有 epoch 屏障隔离。终局胜利时随全部玩法状态冻结。

## 架构与兼容

纯 C# 中新增商人配置、状态、距离／占地规则与独立时钟系统；EquipmentSystem 继续组织购买的库存事务。TackleState 持有商人集合，旧 Stock／Batch／NextRestock 只作为 ID 0 的只读兼容投影，不保存第二份货架。

InventoryCommand 增加 merchantId（默认 0），仅购买允许非零；WithRequest 和编码完整保留。HookInput 仍按各命令长度组合，规则／状态／房间升至 21，输入升至 10，装备地图 HIMF。旧构建、地图和存档明确拒绝；不做旧档迁移。帧同步核心不依赖新增玩法。

Unity 的配置资产、显示、店铺选择和输入与权威状态分离；打开面板、绘制船体与预览不能生成商品或扣钱。自动验收仅在 Editor／Development 显式参数启用，发布程序集不含操作者和驱动。

## 验证与局限

1. 确定性规则：M1 原首批保持；外围首次靠近后立即有货、独立时钟、离开不重置、到期旧请求失败；相同 ID／批次重放一致，不同商人不串货。
2. 真实交易：同店抢购只有一次；不同店可同时购买；离岸／落水／倒地／距离错误／满包／钱不够均不扣钱不移货；失败请求不重放，恢复后售出状态和余时一致。
3. 空间：四条正式最短路可通过普通材料获取和建造到达，船体不可建／不可穿、邻接格可以建，预览与结算一致，地标与 UI 不泄露隐藏等级。扩建与既有敌人／终局的保留格校验一致。
4. 普通输入单人／多人：先捕鱼或钓浮木获得真实材料／金币，铺路到外围商人、打开、买装备，再回程捕鱼；不以运行时注入资源、传送或直接调用成交代替可玩路径。受控验收可关闭敌人／终局及缩短换货间隔，但必须另测正式位置、价格和 600 秒规则，不声称已完成整体战斗／经济平衡。
5. 本机真实 UDP 与原生 1／2／4 客户端：同店抢购、不同库存、完整 checkpoint 一致，至少一次跨货档实际换竿；四人均实际提交购买或观察明确的售出回执。保存／恢复和原房间重开保持身份而重置本局货架。
6. Unity 编辑器、开发／发布严格构建、发布隔离和全量回归；实际查看屏幕外地标、岸边交互、不同商店标题／货架／倒计时和多人购买截图。本机通过不代表公网、丢包压力或长期平衡通过。

最终验收需区分到达所有商人、实际买到一次更高档装备、随机池概率回归三种证据。没有规定每位玩家在一局买齐所有最高档装备。
