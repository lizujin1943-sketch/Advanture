# 钩索小岛背包系统实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将设计中的格子背包接入正式捕鱼、建造、钓竿购买和多人游戏，物品收纳、转移与换包均不丢失、不重复结算。

**Architecture:** 确定性 InventorySystem 管理唯一物品实例及位置；材料、钓竿、空背包共用同一网格和唯一归属。装备与商店系统只调用库存事务；Unity 发送带请求编号的操作，读取确认状态显示结果。库存、掉落和请求回执进入快照及重放，通用帧同步框架不增加玩法代码。

**Tech Stack:** 纯 C# / netstandard2.1、30 Hz 整数模拟、现有可靠 UDP 与 Protobuf 房间协议、Unity 输入与显示。

**Spec:** docs/hook-island-game-design.md（v0.10，背包、换装、材料与商店章节）。用户已要求实现，按现有设计连续推进。

## Global Constraints

- 正式工作目录 /Users/lizujin/Documents/project/git_project/Advanture；保留现有未提交工作。
- Lv1 免费装备，4×4；Lv2～10 为 4×5、4×6、5×6、6×6、6×7、6×8、7×8、8×8、8×9，价格沿用设计表。
- 木材／鱼骨 1×1，每堆最多 20；装备不堆叠；备用空包 2×2，不产生额外容量。
- 钓竿尺寸沿用 RodCatalog；装备中物品不占格。金币为每名玩家独立的钱包，不入包；收鱼者获得收入，购买只扣自己的余额。
- 满包奖励先补堆叠再放空格，余量留在有效平台点，材料包允许部分拾取且不定时销毁；不重复发金币。
- 购买和换包先验证完整布局，再提交；失败保持金币、库存、装备与所有物品原状。
- 允许旋转、移动、拆分、主动丢弃和拾取；不能操作其他玩家的物品；稳定玩家顺序处理共享商店库存和地面物品的争抢。
- 八槽枚举预留，但不生成尚未设计的帽子、衣服等物品。游泳圈的游泳效果属于另一功能，不在背包任务内实现。
- 不把开发自动验证挂为正式场景常驻组件。

## Review Focus

1. 满包直接买大包、缩容失败和丢弃旧包的原子性；物品不能凭总面积判断可装入。
2. 材料溢出与队友部分拾取后的全局数量守恒，平台扣料可跨堆叠，重复命令不得再执行。
3. 钓竿和材料共用容量，钓竿换装不能绕过占格，换包不能补耐力。
4. 快照恢复保留掉落位置／数量、装备、批次和失败回执；输入重放与多客户端结果一致。
5. 非法位置、越权 ID、负数量、重复 ID、重叠、巨大输入、过期商品均明确失败且不部分写入。
