# 阶段 B 首个可运行闭环实施计划

目标：在同一控制台进程中运行一个服务器和两个独立客户端。A 提交输入，服务器校验、组帧、计算并广播；B 收到后执行，各端完整检查点一致。框架保持纯 C#、不依赖引擎、平台和示例玩法。

1. 新建 `FrameSync.Transport`：字节消息接口、连接身份、交付模式、有容量限制的内存传输；先写复制、顺序和背压测试。
2. 新建 `FrameSync.Sessions`：固定名单与连接绑定、分块初始检查点、Ready/Start 握手、明确版本的消息格式。
3. 实现服务器截止时间收集、重复与冲突处理、缺失补齐、确认帧广播；客户端连续执行和逐帧完整状态摘要核对。先写真实三端集成测试。
4. 覆盖边界：时限、身份、旧会话、容量、畸形消息、慢接收、模拟异常、状态分歧、关闭；失败不能伪装为成功确认。
5. 提供控制台演示与交互输入，Counter/Grid 两种示例验证同一框架；补中文注释、运行说明和统一验证脚本。
6. 完整回归、独立复核并修复重要问题。

本次是阶段 B 的第一部分。成员事件/停用与重绑定仍属于后续阶段 B；预测回滚属于 C，持久存档属于 D，可靠 UDP 和多进程属于 E。中途加入、重连和 Steam 接入不在此闭环内。

设计取舍：本次连接与名单由宿主预先绑定，传输采用有界、可靠、有序的内存消息；接口保留不同交付模式和通道。逐帧核对完整检查点摘要便于查错，性能优化后续进行。大快照按块发送，发送受阻时保留队列，禁止丢弃已确认帧。
