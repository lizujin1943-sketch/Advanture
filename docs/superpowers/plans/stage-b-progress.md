## 独立复核与修复

- 复核结论：1 项 Important，无 Critical、无待推迟 Minor。
- 根因：ClientSession.Poll 仅在入口检查终态。Receive(Close) 在循环中切换为 Closed 后仍处理同批 Snapshot；跨通道 Close→Snapshot 是合法顺序，分批到达却不会失败，造成结果依赖 Poll 批次。
- 先增加同批/分批到达的回归测试；只修复“终态后继续收包”的根因，保留等待最后确认帧的关闭行为。
- Final: Ruling: UDP/多进程/成员生命周期继续按明确分期后置 — 当前闭环已证明字节协议与独立状态，但不能代表真实网络 — 后续接入需要对应故障与平台测试。
- Final: Ruling: 运行中客户端停更、自动重连及客户端故障回传由后续连接生命周期处理 — 本次公开 Status/Failure，宿主可关闭，服务器有界等待 — 宿主忽略错误时房间会停在窗口上限。
- Final: Ruling: 容量不一致可以开局失败 — 明确拒绝优于截断输入或错误确认 — 宿主要为所有端提供相容配置。
- Final: Ruling: TrySubmit 成功仍可能被服务器因截止或窗口拒绝 — API 已明确只表示本地入队 — 宿主不能把它当成动作已获确认。
- Final: Ruling: 不宣称性能或商业发布就绪 — 功能与长跑测试尚不能替代性能、平台和网络验证 — 后续游戏接入仍需实测。
