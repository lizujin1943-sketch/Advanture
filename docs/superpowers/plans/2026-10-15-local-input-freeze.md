# 先冻结本地输入，再预测远端输入

用户要求：每个活跃本地玩家的待预测帧，先确定输入并冻结；没有操作也显式提交中性输入。框架保持纯 C#，补齐中文注释与测试。

## 任务 1：核心约束

先增加回归测试并观察失败，再修改 ClientPrediction / ClientSession。未收到服务器最终帧时，本地活跃且缺少已冻结输入就停止推进；不跳过缺口。已冻结输入不可改写。最终帧优先，可在没有本地输入时执行，非活跃成员不要求输入。去掉先预测本地中性值再标脏重算的路径。远端默认预测对方已提交中性输入，服务器补位仍会触发来源差异校正。

验证：核心测试全部通过，覆盖输入缺口、中性输入、字节复制、队列满、最终帧优先、远端差异及分批回滚。

## 任务 2：宿主接入

控制台按固定时钟冻结连续输入帧，空帧也提交；新操作不能改写已经冻结的中性帧。网络背压时保留帧号和输入，过期后丢弃该帧，不能偷偷改派到下一帧。自动脚本逐帧填充中性输入。预测验收工具同样逐帧提交，并检查全部来源和冻结进度。

验证：输入调度测试先失败后通过；真实 UDP 进程验证有操作、无操作、保存恢复和离线成员；两种示例各 1/2/4 客户端故障网络一致性和独立重放。

## 任务 3：文档与完整验收

更新接入顺序、输入来源语义与相关中文注释；运行 ./scripts/verify.sh；保留测试日志；对本次增量做一次独立审查。

Review Focus：权威帧优先与本地输入缺口、局部重算中的冻结输入、初始非活跃成员、宿主多次 Poll/同一时钟值/背压与过期帧、确认帧来源计数、零操作空闲运行。
