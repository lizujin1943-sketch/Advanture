# 倒地救援与付费复活 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 队友免费救起倒地玩家；死亡后个人付费复活；全队死亡且无人付得起费用时失败，全流程确定性联机同步。

**Architecture:** 独立的 RevivalConfig、RevivalSystem、RevivalStateCodec 管规则、结算与校验；HookGame 只编排固定帧顺序。Unity 只发送扶起目标／复活请求并显示确认状态。新增支出账本与死亡代号，复活扣款、位置和资源恢复原子提交。

**Tech Stack:** 纯 C# / .NET 8 验证、netstandard2.1 运行库、Unity、现有 UDP 帧同步。

**Spec:** 本文的确认规则及 docs/hook-island-game-design.md 的角色、落水、个人金币规则。

## 已确认规则与实现选择

- 用户确认：队友救起不扣金币；倒地 60 秒后死亡；死亡玩家各自付费复活；全队死亡且无人能支付自己复活费时失败。
- 默认费用（实现选择，均可配置）：10 G + floor(本局模拟时间 / 300 秒) × 5 G + floor(死亡时个人余额 × 10%)。死亡时锁定报价，付费成功时扣一次；不足全额不能复活，不扣成负数，不动队友钱包。等待不会继续涨价。
- 默认扶起（实现选择，均可配置）：双方岸上、距离 1.5 m 内，按住 R 3 秒；恢复 30% 最大生命，最低 1，不补耐力／饥饿。水中倒地者先钩回岸边；钩拉本身不复活。
- 走动、出钩、松键、离开范围、被拖拽、受伤、倒地、菜单／交易中断救援并清零。多人救同一人不加速，当前有效救援者优先，否则按槽位稳定选择。
- 救援完成优先于同帧倒地超时；倒地倒计时在水里和拖拽中照常推进。最终死亡解除钩索连接，不能继续被钩或救起。
- 付费复活到出生点附近真实可站且无人占据的位置，先找位置再扣钱；默认满生命、满耐力，保留装备、背包和饥饿。找不到位置失败且不扣费。
- 保持帧同步框架独立；输入、状态、地图和握手版本一起递增，不默读旧快照。

## Review Focus

1. 倒地超时与救援完成／钩救上岸同帧，必须确定性且没有重复复活。
2. 费用增长和百分比的大数、零余额、正好够付，全队判败不能误把倒地当死亡。
3. 过期请求、失败请求、读档后重发不能二次扣费，金币账本守恒。
4. 多人救援争抢、施救者受控／倒地，进度不能串人或保留不合法关联。
5. 复活出生位置拥堵、水中死亡、死亡时钩线仍连接，不能扣费后卡住或保留悬挂连接。
