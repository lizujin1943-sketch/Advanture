# 钓鱼连击实现计划

依据：`docs/hook-island-game-design.md` 的已确认连击设计及 2026-10-27 HUD 动效补充。用户已要求直接实现。

## 实现边界

- 确定性模拟负责个人连击、出杆结局、金币奖励和断连；Unity 只读取确认态并播放动效。
- 鱼、浮木、小／稀有宝箱在成功结算事务中计数；大型宝箱在抵岸锁定参与者时计数，开箱不能再次计数。
- 有效钩队友保留连击；空杆、取消未完成收获、脱钩、落水、倒地、死亡、离线及新局按设计清零。
- 第 3 次起显示；金币百分比依次 10、15、20、25、30、35、40、50，10 次起封顶，次数继续增长。
- 多人鱼获取最终参与者更新后的最高连击加成，全鱼结算一次再分配；其他奖励不加成。
- 配置、计数及未结算杆状态进入地图／快照兼容性标识；不修改通用帧同步核心。

## 工作顺序

1. 添加可失败的鱼获奖励回归测试，确认现有实现缺少第三次奖励。
2. 实现独立配置与连击规则，接入鱼、浮木、宝箱事务及各断连路径；覆盖失败回滚、队友钩救与水中重建。
3. 扩展快照／版本兼容性，验证恢复不重复奖励和四客户端确定性。
4. 实现独立 HUD 表现类与可配置 Unity 资源：按最新要求仅显示 `xN`、从绿渐变为红，保留数字弹跳以及随封顶加成变化的字号／高亮；不显示金币加成或图标。使用原创 0–9／x 艺术字，前倾切角、粗笔画、描边及厚阴影。
5. 同步 Unity 依赖、编译并检查实际显示；运行相关模拟、网络与存档验证；由独立审查代理做最终代码审查。
6. 更新设计文档的实现状态和验证记录，明确未覆盖的实机体验。

## 验收重点

- 收获成功次数和奖励同事务提交；溢出／材料失败不能偷加连击。
- 收钩结束不能把已经成功收获或钩救的杆误判为空杆。
- 大宝箱抵岸后恢复快照／重复开箱不增次数；入水只在状态切换时清零。
- HUD 只追随确认态，重复 GUI 绘制不重播，10 次以后表现强度封顶。
- 测试和截图放在 `artifacts/fishing-combo/`；不添加正式场景常驻验证组件。
