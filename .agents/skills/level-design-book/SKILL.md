# 关卡设计：从玩家行为到可试玩空间

依据 [The Level Design Book](https://book.leveldesignbook.com/)，Robert Yang 发起、与 Andrew Yoder 等贡献者共同编写。本文是中文提炼与工作流改编，并非原文翻译；按 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/) 发布，详见 [来源与许可](references/sources.md)。新增 CS 专项为对三份独立资料的原创中文综合与操作化；原资料权利另计，出处、版本与研究范围见 [CS 来源](references/cs-sources.md)。

把每项空间决策写成：**目标行为 → 空间／信息安排 → 玩家可感知的取舍 → 试玩证据**。设计建议是待验证假设；图纸、漂亮截图和生成成功都不能证明关卡好玩。

## 先判断任务

- **新关卡**：读取现有设计、角色控制与相机参数，产出可搭建方案。
- **地图评审／迷路／不公平**：先找问题位置、玩家行为和证据，输出局部修改与验证方法，不顺手重做全图。
- **白盒或场景制作**：只有用户要求实际搭建时才操作引擎；先验证关键空间，再扩展。
- **纯美术地编**：聚焦地形、体块、植被、材质、灯光和可读性，保留已经成立的玩法。

只询问会改变方案的关键缺口：玩法与视角、玩家能力、目标受众／人数、时长与资源、现有地图和任务阶段。已有答案直接沿用。缺少运动／相机参数时先给标记清楚的假设与测试场，不编造“标准门宽／跳距”。小需求不强制完整设计文档。

**CS 类任务先读竞技 FPS 专项**：沿用项目机制，未知时明确标注 5v5、无重生、双包点爆破只是工作假设。先检查完整回合的控制权变化，再检查局部交火；不把“三路”“守方提前几秒”“最多两个入口”当硬约束。

## 核心执行顺序

1. **定义体验**：写出玩家在关键位置应该学会、感到或做出什么；用少量设计支柱处理冲突，避免只说“有趣、宏大、非线性”。
2. **先测不确定项**：核心机制未稳时做运动／战斗测试场。范围过大时先完成最小可玩片段，用实际制作成本估算后续。
3. **组织关系**：用节拍表说明活动、信息与因果；用节点连接图说明主进程、可选路径、门控、捷径、回返和垂直关系。区分真实可达、视线可见、玩家以为可达。
4. **落到空间**：给区域明确的功能、入口／出口、重要视线、危险和选择。尺寸绑定游戏实测指标与相机；不要照搬 Doom／Quake 数值。
5. **白盒验证**：先用低成本几何体测试移动、视线、碰撞、玩法和 AI，允许重做。需要验证视觉机制时尽早加入必要灯光或占位美术。
6. **渐进制作**：脚本、灯光和美术分轮加入，每轮复测原有行为。按类型调整顺序，叙事空间和纯美术任务不必照搬竞技地图流程。
7. **证据驱动迭代**：记录版本、观察和解释的区别，优先修改阻断核心目标的问题；没有运行或试玩时明确写“方案／未验证”。

## 必须保留的判断边界

- 空间 flow 是移动与决策体验，不等于心理学的心流；关键路径是设计模型，不是玩家必须遵循的唯一解。
- 地标、可达性、目标信息和一致的视觉语言可以协同引导；不要宣称“引导线会让玩家自动走对路”。
- 形状／颜色的意义依赖机制、文化和学习；不要把“红色危险、圆形安全”当普适心理规律。颜色提示要有形状、位置或文本等辅助。
- 掩体的价值取决于暴露与移动选择；高地、长视线、环路和对称都不会自动带来好玩或公平。
- 规则是诊断工具，和具体游戏机制冲突时说明取舍并测试。原书有 WIP 和相互张力，不替它补成确定结论。

## 默认交付

新设计给出：简短设计意图、标注假设的区域／连接方案、关键取舍、最小白盒步骤、试玩问题。评审给出：**位置 → 观察／证据 → 影响 → 修改 → 验证**。根据任务需要补节拍表、尺寸表或图，不机械输出所有附件。

示例调用：`使用 $level-design-book，为类似 CS 的 5v5 双包点爆破设计首版地图，给出控制权连接图、到点时间测试和安包／回防验证方案。`
