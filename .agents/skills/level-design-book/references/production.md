# 脚本、灯光、环境美术与发布

原书是关卡设计读物，不是完整引擎、材质或性能手册。下述通用流程来自对应章节；现代 API、平台预算和工具支持需另查官方资料。

## 脚本与门控

**[原书：Scripting / Doors]**

- 先说明行为、状态和时序，再原型最小可玩实现。任务／谜题可用流程图，演出可用台本／分镜；局部脚本无需一律做成全游戏通用框架。
- 触发器是事件来源，门控是限制进程的机制，两者并不相同。多人规则影响玩家判断的区域应清楚可见。
- 门涉及移动、碰撞、遮挡、锁定、AI、声音和任务状态；先确认是否真的需要门。滑门通常比旋转门简单，但仍需考虑设定与玩法。
- 区分开启／关闭中、停住、锁定、假门、可撬锁门等状态；临时全局锁门结束后应恢复原本状态，而非把所有门一律打开。
- 演出要管理 NPC 的常规 AI、动画、物理和周围干扰，结束后恢复；复用既有角色控制而非维护第二套走路系统。
- Navigation 页面只是提纲，不足以作为 A*、NavMesh 或导航算法实现教程。

**[操作化]** 对关键任务检查重复触发、逆序到达、提前离开、死亡重试、读档和多玩家同时操作；保留可恢复路径。实际要覆盖哪些情况取决于游戏是否支持这些行为，不机械扩充系统。

## 功能性灯光

**[原书：Lighting / Three point / D6 / Darkness]**

灯光传达深度、空间、方向、威胁和氛围，不能等同最后的装饰。需要时在白盒阶段就加入。

建议分轮：全局光 → 重要路径／入口出口 → 战斗与谜题 → 情绪及细节。每轮检查是否破坏上轮的可读性。

- 区分可见灯具与实际引擎光源；一个灯具可以支撑多个辅助光源。效果优先，不强求所有光都物理精确。
- 三点布光的主光、补光、轮廓光依赖相机与物体关系；自由移动视角必须检查多个接近方向。
- D6 用骰子六面记忆空间布光，而非只服务单一镜头。原页只展开焦点、框景，路径／边界只有一句；空间、带焦点空间和带框景路径空间仅有标题。不得补写为原书的六套完整教程；额外示例须标注为自行演绎。
- 通常用对比和轮廓维持夜景可读性；若黑暗本身是恐怖或探索机制，则按机制验证，不强制“任何地方都明亮”。

**[操作化]** 在真实相机、曝光／后处理与目标显示条件下检查敌人、出口、危险和交互物；不要只比较编辑器截图。颜色提示配合其他信息，兼顾辨色差异。

## 美术地编

**[原书：Environment Art / Texturing / Psychology / Worldbuilding / Storytelling]**

- 大形、体块、模块与主要材质先行，再做植被、杂物和细节。按区域／主题推进多个粗略资产，再在同一场景评价整体，而非逐件独立做到满精度。
- 用概念图定方向、paintover 反馈白盒、model sheet 说明资产构成与使用情境；资产清单区分重要度、已有与待制作。
- 独特地标资产放在有意义的位置，帮助区域识别、记忆和多人报点；不要把注意力平均分给无关细节。
- 聚类细节、维持大面积信息层级，减少会掩盖敌人轮廓／出口／可行走面的噪声。找物和 prop hunt 等玩法可以故意依赖杂乱，需按玩法判断。
- 建立一致的“可用／不可用”视觉语言，例如植被覆盖与入口可通行的对应关系；美术替换后复查碰撞和导航，不把装饰可见性等同逻辑可达性。
- 材质要能表达用途：金属／木材、穿透、脚步声、破坏性等；贴图在不同距离仍应可读。模块接缝可以通过合适道具遮掩，但不能遮住关键通路或制造误导碰撞。
- 建立 prop zoo／资产展示场，在游戏中并排检查尺度、轮廓、材质、碰撞与风格一致性。
- 环境叙事暗示过去事件；正在发生的事情更多依赖演出与行为。关键叙事信息应与玩家必须理解或使用的行动结合，而非全塞入可错过的小纸条。这一建议在书中引自 Emily Short。
- 颜色和形状意义来自上下文、文化与机制学习。反对普适心理学不等于反对色彩对比、颜色编码或可读性设计。

## 性能

**[原书：Optimization]** 在目标设备上先 profiling，区分 CPU、GPU、内存／加载问题，再选择干预。布局、可见距离、活动 NPC、灯光阴影、材质和资产密度都会影响预算。

**[操作化]** 报告测量场景与硬件、问题帧／区域、瓶颈证据、改动及复测。不要把 draw call 数量等单一指标当总性能，也不要照抄书中的设备预算表。遮挡、分块、LOD、合批和实例化各有条件与成本；检查实际渲染管线。

## 发布与记录

**[原书：Release]** 交付可玩的包、入口说明、所需依赖、署名、主要区域截图与实际游玩片段。作品集还需说明设计过程与取舍；不只展示漂亮墙面。

**[操作化]** 在干净环境验证包能打开且必要资源齐全，区分 alpha／beta／完成状态，记录已知问题。书中对操作系统、压缩格式和作品集平台的偏好属于历史建议，按实际受众和平台要求选用。准备材料不代表已获准公开发布或向外部联系人发送。
