# 空间、节奏与导航

本文按问题组织，原文章节见 [sources.md](sources.md)。标记 **[原书]** 的原则来自该书；**[操作化]** 是为 AI 使用补充的记录方式，不能反向归因为原书规定。

## 目标、范围与调研

**[原书：Introduction / Pre-production / Scope / Research / Worldbuilding]**

- 从实际机制出发：同样是到达出口，跑跳、射击、潜行需要不同空间。不要只按类型标签套现成地图。
- 体验目标用玩家视角表达，例如“先从掩蔽物观察守卫，再选择绕行或正面突破”。设计支柱用于决定冲突时保留什么。
- 计划用于协调和发现问题，不能替代原型。原型分别回答用途、技术可行性、外观手感；垂直切片检验它们能否整合及制作成本。
- 研究参考时分清观察、解释和借用：实地／虚拟走访、平面图、重建练习、截图 paintover 和 moodboard 各回答不同问题。学习参考的构成关系，不复制来源的表面装饰。
- 最小世界观只需回答：谁建造、谁正在使用、玩家能改变什么，以及玩家怎样知道。规模需要时才扩展地图、时间线和笔记。

**[操作化]** 为每个设计支柱补一个可观察信号。比如“侦察后决策”对应玩家是否停留观察、能否说出两条路径的风险差异。信号不是强制 KPI，叙事体验也可用开放式访谈验证。

## 节拍与强度

**[原书：Pacing]** 节拍是事件／活动单元；节奏同时涉及信息、因果、重要性和强度，而非只增减怪物。

- 教授—测试—变奏（teach, test, twist）适合需要学习的机制；变奏不必紧跟教学，不能每个房间都强迫引入新机制。
- 可先独立原型多个战斗／谜题，再筛选编排；与先做整体结构并不互斥。
- 高低强度交替，保留恢复和消化信息的空间。情绪强度不等于操作难度；强度曲线是设计估计，不是科学测量。
- Set piece 是独特、昂贵、值得记住的节拍，可以是安静的场景；先证明关键效果能完成再扩大投入。不要据此强制每张小地图都有大型演出。
- 单人可编排主进程；多人节奏更多由规则、到点时间和资源循环产生；开放世界用区域层次与密度调节，不虚构所有玩家统一的分钟表。

**[操作化]** 节拍表按需写：区域、玩家活动、新信息、预计强度及理由、进入／离开条件、恢复方式。时间先给范围，试玩后更新。

## 布局、流线与拓扑

**[原书：Layout / Flow / Circulation / Verticality / Critical path / Typology / Gates]**

- 布局图是沟通假设的工具；空间 flow 涉及身体移动、视线、信息和做决定的体验，与心理学 flow state 不同。
- 分清几何连接、可通行连接、视觉连接与叙事暗示的连接。图上相邻不代表角色可达，能看见不代表能走到。
- 用线性序列、分支、环路、中心辐射等结构描述不同选择和复用方式；拓扑本身不是质量评分。
- 关键路径用于表达最低完成要求或理想进程；不总是最短路线，也不等于玩家实际路径。开放世界、多人和涌现玩法不应强塞唯一主线。
- 流程允许先空间后任务；原书用 GoldenEye 反驳“必须先确定全部任务才能设计空间”。关系图是一个起点，不是每次必须先画的表格。
- 连接处、楼梯和转角也是玩法空间；环路可能形成捷径、侧翼与迷路，死路可用于奖励或悬念，不必一概清除。
- 垂直性改变信息、风险、重返成本与空间记忆。检查能否看到上下层关系、坠落后能否返回、上行和下行是否对等。
- 门控包括硬阻断与软约束；说明限制目的及绕过后的后果，不把所有偏离主路都认定为错误。
- Parti 是布局核心概念；原页面很短，不能据此声称有完整的构图方法论。

**[操作化]** 先画功能节点图，再映射平面／剖面；每条边标注方向、前置条件、视线和回返方式。解谜及钥匙锁设计检查前置依赖是否成环、钥匙是否被锁在自身后方；这些是落地检查，非原书定理。

按项目需要，检查钥匙、能力、遭遇、单向落差，以及信息／资源不足怎样限制进程；这些是操作化分析维度，不表示 Gates 页逐类给出了完整教程。

## 体块、地形与构图

**[原书：Massing / Landscape / Composition / Prospect-refuge]**

- 先设计主要实体和空隙、包围与开放、体量层级，再用细部支持。体块同时决定空间感、遮挡、通行和战斗。
- 地形不是在噪声高度图上撒资产：先组织区域邻接、主要交通与空间尺度，按需要参考地质、水系、气候／生态，再逐步形成坡面、边界、遮挡、地标及远景。可信度不要求先完成全面生态研究。
- 远景、接近路径和地标共同塑造构图；从真实玩家视点反复检查，而不是只检查编辑器鸟瞰或一张英雄截图。
- 原书反对把 leading lines 当通用导航解释：静态图片的线条分析不能预测可自由转头、受目标驱动的玩家。要研究他们看到什么、认为哪里可达、为什么想去。
- 原书批评 Prospect-refuge（眺望—庇护）的理论依据及游戏迁移，建议改用视线、远景、掩体、围合和安全区等具体概念。安全感随敌人、存档、UI、音频和进度风险改变，不能只从几何推断。

**[操作化]** 每个关键接近方向记录：第一眼可见对象、当前目标、可走路径、遮挡／危险、玩家选择理由。把地形植被的艺术聚类与碰撞／导航数据分别检查。

## 尺度与模块化

**[原书：Metrics / Modular kit / Doom metrics / Quake metrics]**

- 尺度以角色碰撞、移动速度、跳跃、姿态、武器、镜头和 AI 为参照；真实建筑尺寸只提供参考，不能直接等于游戏舒适尺寸。
- 先做测试场，验证门洞、转角、台阶、坡道、跳台和射程。模块网格服务于玩法指标，必要时允许例外。
- 模块套件用 loopback 组装测试证明可组合性：转角、封口、内外墙和复杂拼接都要实际搭。不要只在资产列表中检查单个模块。
- Doom／Quake 的单位、速度、生命伤害和跳跃规则是特定游戏资料，不是 Unity 默认值或跨类型标准。

**[操作化]** 尺寸表列单位、来源／测量条件、目标范围、容错、验证状态。参数未知时用相对尺寸和候选范围；精确数值只能作为明确标注的原型假设。

模块原页是提纲，loopback 只有标题；上面的详细拼装检查是根据测试意图补充的操作化步骤，不是原文已经展开的教程。

白盒也有适用边界：Firewatch 的核心疑问涉及景色与接近最终效果的对话，需垂直切片；Goose Game 的英国村庄可信度需要地点研究。若体验依赖这些内容，纯灰盒不是充分验证。

## 玩家引导

**[原书：Wayfinding / Composition / Environment Art]**

- 寻路涉及定向、路线决策、移动中的确认和目标识别；用路径结构、地标、标识与地图等多种信息，而非只放箭头或灯。
- 入口处让玩家理解目标和可能行动；关键决策点在做决定前提供信息，选择后给确认。
- 强化区域身份、可记忆地标和稳定的视觉语言。多人 callout 是协作信息工具，不只是美术特色。
- 有意迷失可以服务恐怖或探索；必须区分想要的不确定与没有信息、目标、反馈造成的挫败。
- 原书导航辅助表的百分比是作者明确说明的非科学示意，不可当作实测成功率。玩家可能看见、理解主路却主动探索；分别检查看见、理解、选择三个环节。
- 颜色、灯光和物件的意义要在本游戏中保持可学的一致性，不诉诸普适颜色／形状心理学。

遇到迷路，优先定位具体决策点，再检查目标、可达性、地标可见性、区域差异和返回反馈，最后比较修改前后的实际行为。
