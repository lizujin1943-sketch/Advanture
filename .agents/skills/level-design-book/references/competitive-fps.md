# CS 类竞技 FPS：空间要支持可学习、可反制的团队决策

用于低击杀时长、回合制、有限生命的战术 FPS；双包点爆破为常见应用，人数、道具和规则以项目为准。出处缩写：**[GDC]** Garozzo／Snelling 2015 演讲，**[D2]** Johnston 制作回顾，**[WoLD]** 2013 布局教程；**[操作化]** 是本 skill 提出的可测工作方法，不冒充作者结论。准确研究范围和章节定位见 [来源](cs-sources.md)。

## 先确定空间服务哪套规则

**[WoLD：Know your game / Scenario；GDC p7]** 先理解具体游戏，才有资格迁移地图经验；攻守身份依模式变化。爆破安包前通常 T 攻 CT 守，人质模式相反；爆破安包后，空间任务又改变。

**[操作化]** 沿用代码和设计文档，优先确认会改变当前方案的参数：人数／重生／换边，移动与持枪速度、急停、跳跃／蹲伏／双架，镜头与碰撞体，武器伤害／精度／穿透，声音，投掷物及携带数量，回合／安拆包计时与经济。未知项写假设和校准测试；不要把旧 CS 的秒数、单位、烟雾机制或地图状态直接填进自研游戏。

## 简单拓扑，明确的控制收益

**[D2：Keeping It Simple；WoLD：Main Path / Connecting Path]** 借用清楚的连接关系和战术选择，不复制 Dust 2 外形。区分去目标的主路、横向联络路和目标；联络路让受阻队伍换策略，不必退回出生点。并非每条主路都需要联络口。

**[操作化]** 在节点图上分开画通行、视线和投掷连通；每条路注明争夺点、失去控制的后果、撤回／转点代价。若设计中路，说明控中获得哪些夹击、信息或轮转机会；中路和三路布局均非必需。检验新增连接是否让绕后无代价、让防守处处被穿，或让每次佯攻都能免费撤回。保留有理由的承诺成本。

**不要硬套数量**：WoLD 建议两三条主路，但同文把 Dust 2 数为四条；GDC p9 的 Cache 又标四处卡口。先统一“主路、分支、入口、卡口”的统计口径，数量由人数、信息负担和可守性验证。

## 时间决定第一条战线，控制权决定后续战线

**[WoLD：Choke Points；GDC p8–12]** 卡口不是任意窄门，而是争夺进入区域的控制位置。WoLD 提议双方近同时到，或守方稍早形成防线；这是首轮布局启发式，不是每处必须守方提前固定秒数。

**[操作化]** 量测所有相关出生位在不同武器／走跑状态下到达“首次看见、首次可攻击、能安全站稳、到达目标”的时间范围。检验最优出生能否越过整条防线、抢到不可反制角度；同时测试慢位是否只能送死。用几何距离估计找问题，再用实际控制器计时。不要把相同到点时间等同于公平：准备姿态、掩护、投掷物和射角也要算。

进入中盘后，画已控／未知／争夺区域，重新判断防线、转点和回防；开局路线图不代表整轮固定所有权。

**[GDC 约 2:30–4:11]** 讲述将 Cache 视作三路、四处中央卡口，四处只是作者认为适合该类人数的起点，也承认三／五处可能成立。T 的默认展开可以先防 CT 前压；CT 前压获得“此侧暂时没有进攻”的信息后能释放其他防守者轮转。不要把攻击方写成每轮必须立即前冲、防守方写成永不前推。

## 交火要能分解威胁，强位要有代价

**[GDC p10–12]** CS 的惩罚性使同时处理过多危险方向成为问题；Cache A 图示用于讨论防守位和视线。

**[GDC 约 4:45–5:39]** 少量站位通过交叉火力也会产生很强压力；作者特别反对新手到处堆掩体。新增每个掩体先检查它带来的藏人／清点负担与真实战术收益，不把例子中的常见站位数定为配额。

**[操作化]** 从真实玩家眼高与常用姿态，逐段进入区域，标出每次露出新增的危险方向。检查能否逐角清点、队友补枪／同步拉开、用道具隔离一部分火力。入口总数不等于同时需处理的角度数，俯视图线段也不等于真实暴露。

WoLD 的“单一卡口避免超过两个不能同时看到的入口”应理解为控制信息负担的经验，而非全包点最多两入口。不要为满足数字把地图改成一人一枪就能封死的走廊。检查枪位的观察、击杀、退路、补防和反制，优先修无代价统治，而非抹平所有优势。

**[操作化：出生视线评审]** 中路能看到对方出生门时，分别查观察、杀伤和安全横穿窗口，测试最优出生、狙击预瞄、烟雾与绕行成本。狙击对抗可以成立，但“很刺激”不足以证明被迫出门的一方有选择；先提出局部遮挡、路线或时间调整并复测，不自动删整条长线。

## 高差、双架和技巧跳：技能收益不能变成单一答案

**[GDC p13–18]** CS 语境下适度使用高差，避免持续大幅上下追瞄；双架可奖励团队规划。技巧跳应适量，不宜过强或把优势过度排他化。Cache 的跳跃例子同时具有难度、耗时、危险和收益。

**[操作化]** 对高位写清：单人／队友如何到达、需要谁停留、形成站位耗时、暴露／声音、看到什么、如何撤离、敌方如何识别与处理。检查站蹲眼高、武器模型和可命中身体的一致性，避免利用缝隙形成实际单向优势。关键目标不能只靠一个高难跳才能合理处理；若使用技巧捷径，测试普通路线或团队手段的可行性。这里不规定所有游戏都低敏，也不禁止多层地图。

## 穿点与道具：把反制做成实际机制

**[GDC p19–21]** 穿墙射击能奖励地图知识，并反制强守位；Crown 门侧的可穿区域是具体案例。应适量使用，效果取决于武器、材质和厚度。

**[操作化]** 为关键材质列阻视／阻弹／可穿／可破坏属性，实际测伤害、角度、可识别线索与双方风险。不要让外观相同墙面在无反馈下随机可穿，也不要把所有掩体都做成无用薄纸。

**[GDC 约 11:00–12:12；操作化边界]** 演讲补充穿点会消耗弹药、发出噪声并暴露位置。不要把“扫过却没有击杀”视为该区域必定无人：伤害、覆盖范围、反馈和敌人移动都会使这种推断失效。

**[操作化：道具扩展]** 对每个关键卡口和强位，检验烟能否切断所需视线、闪能否配合队友推进、火能否清角，以及接收方能否退、反道具或再争夺。以项目已实现道具为准；没有烟／闪／穿透时，不能声称这些已经提供反制，需用几何和路线补足。检查投掷空间、碰撞、反弹、烟边和顶界；“有反制”不代表必须固定阵容、固定投法或耗尽整队资源才可正常进点。

## 包点要连同安包选择、守包与回防设计

**[GDC p22–25]** 安包区域不是随手放的触发框。Cache A 的示例区分安全包、面向 Main 和面向 Middle 的包位：安包时更暴露的选择，可以换取安包后从已控路线守包的便利。这是风险收益关系，不是所有暴露包都必然好守。

**[操作化]** 每个候选包位记录安包暴露、队友掩护需求、可守包方向、敌方拆包接近／隔离路线、声音与剩余时间。验证安包范围、遮挡和拆包交互一致。一个包点既要能攻入和立足，也要允许有条件的守包与回防：不要只用“攻点成功率”评价整点，不要把回防入口数量误当作开局进攻入口数量。

场景无法守包时先查包位、存活人数、控区和道具；回防总迟到时先查信息延迟、转点距离、清点和拆包耗时，再决定移出生、改包点或增连接。采用 [分阶段验证模板](competitive-fps-validation.md)，避免用总体胜率掩盖两个相反问题。

## 美术也是竞技规则的一部分

**[GDC p27–51；D2：Arches / Road / Trim / Alpha]** 几何分区、轮廓、出口、克制细节与背景辨识共同服务交战；美术和玩法不能割裂。Dust 的拱门同时划分区域、收束交火和截断视线；道路与包点箭头支持认路。天空盒还能承担投掷物参考及场景表达。

**[操作化]** 在实际交火距离，用双方人物／皮肤、站蹲姿态和目标画质检查轮廓、亮度与颜色干扰；亮一点或饱和度低一点不自动解决辨识。保持入口层级、可行走／可跳／可穿材质语言一致；清掉卡脚小物、误导性小缝和无价值藏人细节。地标和报点名称要便于队友迅速交流。投掷参考应稳定、可复现；视觉地标和实际阻挡投掷物的天空边界分开核验。

作者关于辨识促进留存的链式说法是设计主张，不是已证因果；Dust 的配色、饰边次数和白天主题是该地图的选择，不是竞技 FPS 的强制美术规范。目标是明确艺术主题与可辨识对抗共同成立，不是一律白墙。

## 快速迭代，而非追认经典必然正确

**[D2：Starting Out / Early / Alpha / Beta / Release；WoLD：Putting It All Together]** 草图用来帮助尽快进入可玩布局；出生、目标、比例和连接都能改。D2 的 B 点通过平台、掩体与新连接迭代，外部反馈改变引导及最终出生／包点位置。

**[操作化]** 先验证最不确定的交火／包位，再接全图测试，真人对抗前的计时和射线仅作筛查。每轮改变有明确诊断的一小组变量，保存版本与结果；引入熟练玩家评估可开发的战术，新玩家评估认路与可读性。历史成功案例不证明其中每个细节最优：D2 的长 CT 出生区部分来自编辑器范围限制，不能反推为必须复制的平衡定律。
