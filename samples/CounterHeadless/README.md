# Counter 一帧多操作示例

核心框架仍把每名玩家每帧的输入当作一段不透明字节。操作封装、校验和执行只属于 Counter 示例。

```csharp
// 原有单操作调用保持原义。
byte[] add = CounterGame.Input(0, 37);
byte[] random = CounterGame.Input(1);

// 玩家本帧按此顺序执行：加 37、随机加法、减 5、随机加法。
byte[] batch = CounterGame.InputBatch(
    add, CounterGame.RandomInput(), CounterGame.Input(0, -5), CounterGame.RandomInput());

// 缺失输入补齐策略可明确使用中性输入。
byte[] neutral = CounterGame.NeutralInput();
```

一帧先按框架提供的玩家位置 `Slot` 升序处理，各玩家的操作再按批次中的原顺序逐项执行。不会排序、合并操作或提前消耗随机数。每个完整帧只增加一次 `Steps`，并沿用原有的帧末事件行为：帧末总数不同于帧初时发出一个总数事件。

`Input(byte command, int amount = 0)` 保持旧行为，包括只编码、由输入验证器检查合法性的约定。`Input(1)` 表示随机加法，`Input(0, amount)` 表示普通加法；没有新增会改变这些调用含义的 `Input(int)` 重载。

## 字节格式

整数均使用小端序；操作不可嵌套。

| 形式 | 字节布局 | 限制 |
| --- | --- | --- |
| 单操作 | `command:u8, amount:i32` | 恰好 5 字节；命令 0 为 Add(-1000..1000)，命令 1 为 RandomAdd，参数必须为 0 |
| 多操作 | `2:u8, count:u8, operation[count]` | count 为 2..16；长度必须恰好为 `2 + 5 × count`，最多 82 字节 |

`InputBatch` 接受 1..16 个合法单操作，返回独立数组。只有一项时直接返回其五字节副本，拒绝使用 `count = 1` 的额外包装，保证该操作列表只有一种编码。空批次、超过 16 项、空项、嵌套批次、非法命令或参数、截断及尾部附加字节均会被拒绝。运行器会在执行任何操作之前完成整帧输入校验。

中性输入是显式的单操作 `Add(0)`，不允许用空字节或空批次表示。`Add(0)` 也可以出现在非空批次里，保留原始位置；它不改变总数、不消耗随机数，但整帧仍正常推进。

输入格式兼容版本已从 `1` 升到 `2`。单操作字节仍可提交，带旧版兼容清单的检查点或录制会被拒绝恢复，避免不支持批次的旧程序参与同一会话。状态格式、既有操作规则和随机数算法未变化。
